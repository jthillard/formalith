# AGENTS.md

Formalith is a computer algebra system library in Rust, generic over the algebraic structure (set/group/ring/field) expressions live in.

Cargo workspace (`crates/`): `formalith` (the CAS library; the `src/...` paths below are relative to `crates/formalith/`), `formalith-session` (interactive sessions shared by the interfaces), `formalith-cli` (binary `formalith`, the default `cargo run`), `formalith-web` (wasm), `formalith-gui` (graphing calculator, egui/eframe with wgpu, native and wasm; not a default member), `formalith-gui-worker` (wasm only: the GUI's Web Worker, see Graphs and GUI).

## Commands

Nightly Rust is required (`#![feature(specialization)]`); `rust-toolchain.toml` pins it, so plain `cargo` works.

- `cargo build`, `cargo test --workspace` (unit, `tests/`, doctests), e.g. `cargo test -p formalith --test integration parser::test_try_parse`
- Build time: iterate with `cargo test -p formalith --test integration <filter>` (a few seconds after an edit; it builds neither the library's unit tests nor the other crates), keep `cargo test --workspace` for the final check, and fuzz with `./dev fuzz --release` (profile `fuzz`: optimized like `release` but incremental, a few seconds after an edit instead of a minute and a half). Profiles (root `Cargo.toml`): `dev` keeps only line tables, dependencies are optimized (`opt-level = 2`, so malachite doesn't slow the tests). Cargo runs sharing a target directory wait for its lock, so run them one after the other.
- `cargo run [expr...]` (`formalith-cli`): REPL (`--set <name>` / `:set <name>`, `--typst` / `:typst`).
- `cargo clippy --workspace --all-targets` must stay warning-free. The crate warns on `clippy::pedantic`, `nursery`, `cargo`, `missing_docs` and `rustdoc::all` (so every public item needs a doc comment), with `many_single_char_names`, `too_many_lines` and `suboptimal_flops` allowed crate-wide in `lib.rs`; other exceptions are local `#[allow]`s with a comment.
- `./dev <command> [--release] [--profile] [--serve] [-- args]` (bash script at the root, `./dev --help`): `repl` (`cargo run -p formalith-cli`), `gui` (native GUI), `web` (wasm package into `crates/formalith-web/www/pkg/`, needs `wasm-pack` and the `wasm32-unknown-unknown` target; `--serve` serves it on port 8000), `gui-web` (GUI into `crates/formalith-gui/www/pkg/` and its worker into `crates/formalith-gui/www/worker-pkg/`, `--serve` on port 8001), `docs` (the documentation page of the builtins, sets and commands into `target/docs-site/`, written by the example `crates/formalith-session/examples/builtin_docs.rs` with the stylesheet and script of `docs/site/`, which render results with typst.ts; `--serve` on port 8002; its examples link to `../repl/?run=<lines>`, which the web REPL runs at startup), `test` (`cargo test --workspace`, arguments after `--` going to the test binaries, e.g. a filter) and `fuzz` (the ignored fuzzers, `cargo test -p formalith --test integration -- --ignored fuzz`, arguments after `--` replacing the filter `fuzz`, e.g. `check_optimize::`; `--release` recommended). `--profile` adds the profiler (feature `profile`, see Profiling; `gui` and `gui-web` only). Without `--release`, builds are debug and wasm builds skip `wasm-opt` (`wasm-pack --dev --no-opt`), for quick testing. With `--release`, wasm builds use the profile `wasm-release` (root `Cargo.toml`: `opt-level = "s"`, thin LTO, stripped) and `wasm-opt -Os`, downloaded by wasm-pack (`[package.metadata.wasm-pack.profile.custom]` in each wasm crate, with the wasm features rustc emits). `wasm-bindgen` is pinned in `crates/formalith-web/Cargo.toml` and `crates/formalith-gui/Cargo.toml` to the installed CLI version.
- `formalith-gui` is not a default member, so plain `cargo build` / `cargo test` skip it; `--workspace` or `-p formalith-gui` include it.
- Tests: the files of `tests/` are modules of one test binary `integration` (`tests/main.rs`, `autotests = false`), since each binary links the whole library and dozens of them made builds disk-bound; `tests/*.rs` compare results with hand-written ones; `tests/check_*.rs` check results against their definition (derivatives of antiderivatives, substituted solutions, sampled regions and extrema, partial sums, `approx` against `Numeric`...) with the helpers of `tests/common/` (`harness::check_all` for curated cases, which must not be skipped, `fuzz` for seeded random ones, `assert_pass` for regressions `bug_*`). Fuzzers are `#[ignore]`d: `cargo test -p formalith --test integration check_optimize:: -- --ignored`, with `FORMALITH_FUZZ_CASES`, `FORMALITH_SEED`, `FORMALITH_SHOW_SKIPPED`, `FORMALITH_TIMES` and `FORMALITH_WORKERS`; `.github/workflows/fuzz.yml` runs them every night with a new seed (`-- --ignored fuzz`, other ignored tests being future work).
- `cargo doc`: doc comments can contain Typst math as `{$ ... $}`, rendered by `docs/typstts.html` at the workspace root (injected by `.cargo/config.toml`).

## Architecture

**Sets** (`src/field/`). Expressions are `Term<T>` with `T: Set` a small `Copy` value describing the structure, used as a constant: `parse!("x^2", R)`. Hierarchy: `Set` → `PartiallyOrderedSet` → `Monoid` (`zero`, `add`) → `Group` (`neg`) / `Semiring` (`one`, `mul` and the `normalize` / `expand` / `simplify` hooks), `Ring: Group + Semiring` → `EuclideanRing` / `Field` / `Derivable`; term normalization and `+` / `*` need a `Semiring`, `-`, `/`, `expand` and the rest a `Ring` (other sets only normalize function arguments). Each set declares its `Element`, an `ExponantSet` (where powers live) and a `ProductCoefficientSet` (coefficient of `Mul`). Concrete sets in `src/field/commons/`:
- `N`: a `Semiring` with `Z` exponents and coefficients; `-`, `/` and negative exponents are parse errors (`ApplyBinary`, `ParseUnary`, `CheckExponent`), `gcd`, `lcm`, `quo`, `rem`, `factorial`, `isprime`, `abs` of values are evaluated and other builtins stay unevaluated. `Z` (`gcd`, `lcm`, `factorial` of values, `factor` through ℚ), `R` (rationals via `malachite`)
- `C`: Gaussian rationals over `CartesianPower<R, 2>`; the identifier `i` parses as the imaginary unit (`exp(q i pi)` is evaluated for half-integers `q`). `integrate`, `lim` and `series` are evaluated in `R` on the real and imaginary parts (`complex/parts.rs`: every symbol is assumed real, `exp(a + i b) = e^a (cos b + i sin b)`, `b^(a + i c)` for positive `b`, the principal `ln z = ln|z| + i arg z` (`ln(u^2 + v^2)/2` unless the root simplifies, `u^2 + v^2` simplified when small, so `ln(exp(i)) = i`) and principal powers `exp(w ln z)` of other bases, `sin` / `cos` of complex arguments, `re`, `im`, `conj`, `abs`; bounds and points must be real), then joined back (`c/d` with a non-real constant `c` written `1/(d/c)`, so `integrate(exp(-x) exp(-2 i pi x t), x, 0, oo) = 1/(2 i pi t + 1)`); a divergent part of a non-real integrand gives `undefined`. Whole series `series(f, x, a, oo)` are first computed in `R` with the imaginary unit as a real parameter `@iunit` substituted back (`parts::with_unit` / `from_unit`, only for rational and entire functions, so that `series(exp(i x), x, 0, oo)` is a single sum of `(i x)^k/k!`), else per part; held sums split into parts by linearity (`parts::split_fun`, their index not counting as a symbol in `parts::is_constant`), so `approx` works on them, and are differentiated in `R` through `@iunit` (`Derivable for C`). In normalization, constants (no symbols but builtin constants, `parts::is_constant`; symbols aren't assumed real there, `re(x)` stays) go through the same parts: `ln` of constants other than positive reals (`ln(-1) = i pi`), `re` / `im` / `conj` after their linearity rules, `abs` of non-real constants, constant radical expressions (`parts::is_radical_constant`: roots of positive rationals or of positive real radical sums, Gaussian coefficients) are rationalized and expanded through their parts like in `R` (`C::expand_radical_product`, negative and integer powers of sums and products of a sum with other radicals or a non-real coefficient; `parts::join_expanded` moves the rational content out: `1/(1 + i sqrt(2)) = (1 - i sqrt(2))/3`), and `approx` (`complex/approx.rs`: each part approximated in `R`, giving a `Value` with the `APPROXIMATE` flag printed by `C::print_approximate` as decimal parts; non-constant terms are traversed like in `R`). `arg(z)` is the principal argument in `(-pi, pi]` from the parts (`expr::arg`: `atan(v/u)`, shifted by `±pi` for `u < 0`, `±pi/2 - atan(u/v)` when only the sign of `v` is known, by the signs of the parts, `undefined` at 0, unevaluated when a needed sign is unknown; in `R`, `0` or `pi`; `R` reduces `atan(tan u)` to `u - k pi` for a constant `u`, so `arg(exp(4 i)) = 4 - 2 pi`). `CartesianPower<T, K>` is only a componentwise group.
- `M`: matrices, with symbolic entries (`M<TermSet<R>>`), whose fractions are simplified by normalization (`A A^-1 = I`). `A^0` is the identity of the size of `A` (`Ring::one_like`). Also `M(C)`, `M(Z)` / `M(Z/n)` in the REPL (`M<TermSet<C>>`, `M<TermSet<Z>>`, `M<TermSet<Zn>>`). Builtins `transpose`, `kernel` (columns of a basis, a zero column for `{0}`), `eigenvalues` (column, repeated by algebraic multiplicity), `eigenvectors` (eigenspace bases as columns, same order), `hermite`, `smith` and `I(n)` and `zeros(n, m)` (sizes parsed in `Z`, evaluated for `1 <= n <= 1000`), `diag(a_1, ..., a_n)` (or a row / column), `roots(p, x)` (roots found by `solve_for` as a column repeated by multiplicity, `eigen::roots`: real ones in `M`, complex ones in `M(C)`, unevaluated without any) and `factorint(n)` (rows `[p, e]`, `[-1, 1]` first for negatives, negative exponents for denominators; `field/commons/primes.rs`: trial division, then malachite's `u64` factorization or Pollard's rho, Miller-Rabin with 13 bases) return matrices (`Context::returns_matrix`), so they are functions of `M` (`M::parse_literal` declines them, and a scalar of `M` being parsed stops before them through `Parser::scalar_of_matrix`, so `2 I(2)` is a product in `M`; other calls parse as scalars) evaluated in `M::eval_builtin`; `simplify`, `expand`, `factor`, `diff`, `subs`, `integrate` and `approx` (`Context::maps_entries`) apply to each entry of a matrix first argument, the others being scalars (`MatrixEntries::apply_builtin`: the builtin of the entries' set, normalized), parsed as functions of `M` when their arguments contain `[` or a builtin returning a matrix, or when the scalar parse fails (a matrix definition), otherwise as scalars; `gradient(f, x, y)` (a column), `jacobian(F, x, y)` (`F` a row or column of functions, or a scalar) and `hessian(f, x, y)` are also functions of `M` (variables as symbols or a row of symbols, every symbol sorted by name when omitted; derivatives through `MatrixEntries::derivative`, for `M` over `R` or `C`); `det`, `trace`, `rank`, `charpoly(A, x)` (`x` by default; Berkowitz, division-free) return scalars and are also evaluated in scalar sets (`fun::eval_matrix_builtin`, in R, C, Z, Zn). Entry-specific parts go through the specialized trait `MatrixEntries`: `M(Z)` uses `matrix/normal_form.rs` (row-style Hermite `U A = H`, Smith `U A V = D` over any `EuclideanRing`, pivots normalized by `EuclideanRing::normal_unit`; rank from the Hermite form, kernel as a lattice basis), `M(Z/n)` lifts to `Z` (Hermite of `[A; n I]` reduced mod n, Smith diagonal `gcd(d_i, n)`; rank / kernel only with invertible pivots), `M` over `R` and `C` have eigenvalues (`matrix/eigen.rs`, generic over `EigenSet`: roots of the characteristic polynomial by `solve_for` in the set of the entries, multiplicities by derivatives, eigenspaces by an elimination testing zero on expanded numerators; unevaluated unless every root is found there, so non-real eigenvalues need `M(C)`).
- `Zn`: `Z/nZ` with a runtime modulus and `u64` representatives; `factor` works on univariate polynomials when `n` is prime.
- `Poly<K>`: `K[x]` (`K.get_polynomial_ring(symbol!("x"))`). Values are whole expanded `MultivariatePolynomial`s, the variable parses as a value, other identifiers stay symbols. `gcd`/`lcm`/`quo`/`rem` and `degree(p)` (unevaluated for `0`) are evaluated, `factor` is not (products of values fold back).

**Terms** (`src/term/`). `Term<T>` is an enum `Value | Symbol | Add | Mul | Pow | Fun`. `Fun` holds `Box<dyn Function<T>>`, so a function's arguments may live in another set than its result (`det` takes matrices, returns scalars). `TermSet<T>` (`term_ring.rs`) is the set whose elements are `Term<T>`s; it makes coefficients symbolic, hence types like `Term<M<TermSet<R>>>`.

**Normalize / Expand / Simplify.** Traits on `Term<T>` using specialization: a `default fn` for plain `Set` (often `todo!()`, so missing structure panics at runtime, not compile time) and real impls for `Ring`. Set-specific rules hook in through `Ring::normalize` / `expand` / `simplify` (e.g. `real.rs`, `matrix.rs`). Terms carry a `NORMALIZED` flag (`term/flags.rs`) to skip re-normalization.

**Parser** (`src/parser/`). Pratt parser, entry points `parse!` / `try_parse!`. Dispatched per set via `SetParseExpression` (`parse_literal`, optional `parse_expression` for e.g. matrix literals `[[a, b], [c, d]]`). Its `MatrixArgumentSet` is the set `det(...)` arguments parse in (`M<TermSet<Self>>` for scalar sets, `Self` for matrix sets); it must never build a bigger set from a matrix set, or the parser is monomorphized over infinitely many types. Sets without `SetParseExpression` fail at runtime. A postfix `!` is a factorial (`n!`, binding tighter than any operator, so `n!^2 = (n!)^2` and `2^3! = 2^6`; `!=` is still the relation), printed so in every output. A number literal directly followed by an identifier or `(`, or a `)` directly followed by `(`, is an implicit product (`2x`, `3(x + 1)`, `(x + 1)(x - 1)`), not with a space (`5 x`). Number literals may have a decimal part and an exponent (`1.5e-20`, lexed only when digits follow `e`, so `2e` is `2 e`), parsed exactly as rationals (`parse_rational_literal`), so `1e-20` is an error in `Z`. In sets whose exponents are integers (`ExponantSet = Z`, except `Z` itself, where `1/2` is a term), an exponent with a denominator is an error (`x^(1/2)` in `Z/n` or `R[x]`, `CheckExponent`).

**Definitions** (`src/parser/environment.rs`). `a := ...` / `f(x, y) := ...` (`Parser::parse_statement`, `Environment::eval`). An `Environment` stores definitions as source text plus a snapshot of the definitions existing when they were made (so no recursion, redefinitions don't affect earlier definitions), and the parser expands them in the outermost set (`Parser::with_environment`, `parse!(input, set, &env)`), so they work in any set. Arguments are passed by name (re-parsed at each use). Names a set reserves (`i`, a polynomial variable) are declared by `SetParseExpression::is_constant`.

**Solving** (`src/solve/`). A statement of comma-separated equations, like `x + y = 3, x - y = 1`, is solved for all its symbols; `solve(a*x + y = 1, x - y = b, x, y)` solves for the listed symbols, the others being parameters (`Statement::System`, parsed by `Parser::parse_statement`; `solve` is a builtin only allowed as a whole statement). Entry point is the `Solve` trait: `solve` (every symbol, sorted by name) calls `solve_for`, specialized (unsupported by default and for `M`, real impl for rings). It writes `lhs - rhs` as a fraction (`as_fraction`), expands its numerator and tries `linear::solve` first (solutions where a denominator vanishes are dropped at the end): coefficients are extracted as terms (`Term::symbols` tells which parts contain unknowns), then Gaussian elimination with `Matrix::row_reduce_left` (pivots only in the coefficient columns) runs in the set itself when every coefficient is a value (when a pivot isn't invertible, `Z` and `Zn` fall back to `solve/lattice.rs`, specialized trait `IntegerSystem`: over `Z` the Hermite form keeps unknowns without pivot free when pivots divide their rows, otherwise both use the Smith form, `d_i y_i = c_i`, `y_i` being a new parameter `t_k` (skipping used names) when `d_i = 0`, and modulo `n` one branch per solution of `d_i y_i = c_i` with `gcd(d_i, n) > 1`, at most 256 branches), or in `TermSet` otherwise, assuming symbolic pivots are non-zero, with results simplified. On `SolveError::NonLinear` it falls back to `polynomial::solve`, a recursive case split (`Branch`): factor equations into one branch per factor, substitute unknowns with a coefficient free of unknowns (`Term::substitute`, `src/term/substitute.rs`, keeping numerators), solve univariate equations, substitute with symbolic coefficients (plus the zero-coefficient branch; the other branch keeps the coefficient as `Branch::nonzero` and is dropped when it vanishes), eliminate with resultants (Sylvester determinant, division-free), and as a last resort solve for an unknown with symbolic coefficients. Set-specific parts go through the specialized `PolynomialRoots` trait: `factor_term` (`Term::factor` for sets meeting its bounds, `Zn::factor`) and `roots` (`R`: degree 1-2 and polynomials in `x^k` with radicals, cubics with rational coefficients by Cardano's formula or its trigonometric form (three real roots), quartics with rational coefficients by Ferrari's method (`quartic_roots`: a positive root of the resolvent cubic, rational if possible), signs of radicals by float approximation since `sqrt` of a negative value panics; `C`: same degrees with `k` a product of 2s and 3s, cubics with rational coefficients by Cardano's formula (`complex_cubic_roots`: the conjugate pair `s - (u + v)/2 ± i sqrt(3)/2 (u - v)` next to the real root, or the three real roots of the trigonometric form), quartics with rational coefficients by Ferrari (resolvent root possibly in trigonometric form, signs then by `constant_sign`; real expressions with functions go to `C` through `complex::from_real` / `to_real`), cyclotomic polynomials `Φ_n` (`cyclotomic_order`) by `cos(2πj/n) + i sin(2πj/n)`, with radicals when they are (`trig_radical`: classic values or sums of two classic angles, so `Φ_15`; otherwise left as `cos(q pi) + i sin(q pi)`, conjugates written `cos(a) - i sin(a)` with `a` in `(0, pi)`, like for `Φ_7`), square roots of non-real values with nested radicals; `Zn`: every residue for small moduli; `Z`: divisors of the constant; otherwise irreducible value polynomials have no roots). In `R`, other polynomials with rational coefficients (degree 5 and more, quartics whose resolvent roots have no known sign, like `x^4 + x + 1`) get their real roots as `rootof` (see Real roots). In `R`, a single equation in a single unknown with non-polynomial parts (kernels: functions of the unknown, `b^u`, rational powers) skips both and goes to `solve/inverse.rs` (specialized trait `Transcendental`, since the polynomial solver hangs on `x + sqrt(x)`): when every kernel is a power of one `g` (`e^(2x) = (e^x)^2`, `sqrt(x)` with `x = sqrt(x) (after dividing out a factor `e^(m u)` common to every term, `x^2 e^(2x) - e^(2x)`)^2`), the equation is a polynomial in `g` solved by `solve_for`, each root `c` gives `g = c` inverted (`sin`, `cos`, `tan` with a new integer parameter `k`, `k_1`... per nesting level skipping used names, `exp`, `ln`, `b^u` with `log`, rational powers, inverse trigonometric and hyperbolic functions, `abs`, `lambertw`; values out of range by `constant_sign`), then solved recursively (bases that are perfect powers share their root, `4^x = (2^x)^2`; hyperbolic functions mixed with other kernels are written with `exp`). `sin`, `cos`, `tan` of rational multiples `n_i u + c_i` of a common angle (`inverse/trig.rs`) are polynomials `P(S, C)` in the sine and cosine of `v = m u` (multiple angles by a recurrence, shifts by the addition formulas), solved as a polynomial in `S` (or `C`) when the other has only even powers, in `tan v` when homogeneous up to `S^2 + C^2 = 1` (plus `cos v = 0`), as `R sin(v + φ) = c` (`φ` by `expr::arg`) when linear, and otherwise with `t = tan(v/2)` (plus `v = π`); branches where a cosine dividing a `tan` vanishes are dropped. The trigonometric polynomials whose roots have no radicals get `rootof` values (`sin(3x) + cos(x) = 1/3`, a sextic in `tan(x/2)`). `a f(u) + b g(v)` with unrelated angles, `f`, `g` being `sin` or `cos` and `a = ±b` constants (`inverse/angles.rs`), is solved by the sum-to-product formulas (`cos v = sin(v + pi/2)`, `sin x = cos(x^2)`), each factor separately. Two terms `t_1 + t_2` whose ratio is a constant times powers with exponents depending on the unknown are solved by taking logarithms (`2^x = 3^(x + 1)`, `x^x = 2`; no solution for a non-positive constant). Otherwise a single kernel gives `lambertw` for `(αx + β) e^(γx + δ) = c`, `a e^u + αx + β = 0`, `a ln u + αx + β = 0` and `b u ln u = c` (`u` linear, `e^u` possibly `b^u`): no root below `-1/e`, `-1` at it, both branches `W_0` and `W_-1` for arguments in `(-1/e, 0)` by `constant_sign` (only `W_0` when a sign is unknown). Last, sums `c_0 + Σ c_i e^(λ_i u)` of exponentials of a common `u` with constant coefficients and rates (`inverse/exponential.rs`, `2^x + 3^x = 5`) have at most `N` real roots, `N` being the number of sign changes of the coefficients sorted by rate (Descartes' rule for exponential sums; none for `N = 0`): roots are isolated in f64 (between the critical points of `e^(-λ_0 u) f`, recursively) and rationals with denominators up to 12 near them are checked exactly; solved when `N` exact roots are found, `Unsolvable` otherwise. Integer parameters are restricted to the values for which the solution is real (`inverse/ranges.rs`): conditions on the bases of even roots, `ln`, `asin` and `acos` arguments of the solution, and on the value `c` of `g = c` for the range of `g` (`range_conditions`: `c >= 0` for `sqrt u = c`, `|c| <= 1` for `sin`...), when affine in a single parameter, bound it: a finite range is listed (up to 100 values), an empty one drops the solution, `k >= k_0` is written `k = k_0 + n` and `k <= k_1` as `k = k_1 - n` with a natural parameter `n`, `n_1`... (`is_natural_parameter`, skipping used names), so `sin(x^2) = 1/2` gives `x = ±sqrt(pi/6 + 2 pi n)`; other conditions leave the parameter unchecked. The parser lists symbols `k`, `k_n` (and `n`, `n_i`) of the solution that aren't in the equations as `Statement::System::integers`, printed as a last line `k ∈ ℤ, n ∈ ℕ` (Typst `k in ZZ, n in NN`, `integers_line`); they aren't assumed integer afterwards (but in `argmin`'s values, natural ones non-negative). A `Solution` gives pivot unknowns in terms of free unknowns, several of them as `Solution::Alternatives` (printed one per line, ` \ ` in Typst), or `no solution`.

**Real roots** (`src/polynom/real_roots.rs`, `field/commons/real/rootof.rs`). `rootof(p, x, k)` (`x` optional when `p` has a single symbol) is the `k`-th real root of a polynomial with rational coefficients, by increasing order. It normalizes to a rational or a square root for linear and quadratic factors, and otherwise to the internal function `@rootof(j, c_0, ..., c_n)` (`Context::real_root`: the `j`-th real root from 0 of an irreducible factor, primitive over ℤ with a positive leading coefficient, so the form is canonical and has no symbol), printed `rootof(p, k)` with `p` in `x` so that it parses back (`op("rootof")` in Typst). Roots are isolated by Sturm sequences (`isolate`: intervals from Cauchy's bound bisected at dyadic points, not containing 0, refined until intervals of different factors are disjoint to sort them) and refined by bisection (`Isolated::refine`). Powers `α^n` with `n < 0` or `n >= deg q` are reduced modulo `q` in `R::normalize`, so polynomials in a single root have a canonical form and zero tests by expansion work (`α^5 - α - 1 = 0`, used by `eigen::real_roots` for multiplicities). The sign engine reads its sign from the interval, `approx` (`Fixed::evaluate`), the CAD and `argmin` approximate it by refining, `Numeric` compiles it as a constant, and its derivative is 0. `rootof::real_roots` gives every real root of a polynomial exactly, used by `PolynomialRoots for R`.

**Optimization** (`src/optimize/`). `argmin(f, x_1, ..., x_n)` / `argmax(...)` (every symbol of `f` sorted by name by default) or `argmin(f, x, a, b)` (one variable and two more arguments which aren't both symbols of `f`: bounds, possibly `-oo` / `oo`) is a whole statement (`Parser::parse_argmin`) giving a `Statement::System` whose `equations` are those of the critical points and whose solution lists every global minimizer (`no solution` when the extremum isn't reached, `x = y` for a line, `k` for periodic points). Specialized trait `Optimize` (unsupported by default, real impl for `R`; `argmax` minimizes `-f`, errors are `SolveError::Optimization`). One variable (`univariate.rs`): the domain is cut at special points (bounds, zeros of the arguments of `ln`, of bases of negative or fractional powers, of `tan`, `asin`, `acos`, `atanh`, `acosh`, `lambertw` domains, of `abs` / `sign` arguments and of the denominator of `f'`); each open interval between them is kept when `f` is defined at a sample point (conditions checked in order, inner ones first), critical points come from `solve_for(f' = 0)` (per interval with `abs(u) = ±u` and `sign(u) = ±1` when `f` has them; a constant piece reaching the extremum is an error), and the minimum is the lowest value at the critical and special points where `f` is defined (`compare`: zero difference once expanded, else `constant_sign`, so assumptions on parameters decide), unless a one-sided limit at an interval end (or at `±oo`) is lower. Periodic points `c(k)` are listed on finite intervals (at most 100) and kept over ℝ when `f(c(k))` doesn't depend on `k` (assumed integer while evaluating; families are first split into classes `c(m k + r)` for the smallest `m <= 4` making `f` and `f''` there independent of `k`, `split_classes`, since `sin u = 0` and `cos u = 0` give a single class `pi k`, `pi/2 + pi k`), limits at `±oo` being then allowed not to exist; periodic special points, `floor`, `ceil` and `piecewise` are unsupported. Several variables (`multivariate.rs`): rational functions without parameters only; the critical point (`solve_for` on the gradient) with the lowest value `m` (branches along which `f` isn't constant are dropped) is the minimum when `f < m` has no solution (`SolveInequality`, so at most 3 unknowns; `m` must be rational, an error otherwise, since the CAD doesn't finish with radicals), otherwise there is none. `localmin` / `localmax` (`Extremum::LocalMin` / `LocalMax`, same arguments) list the local extrema, relative to the domain: one variable through the same `univariate::Analysis` (the domain cut into `Piece`s with their sorted critical points and derivative), a critical point being a minimum when the sign of the derivative, sampled between consecutive critical points, goes from `-` to `+` (so `x^4` but not `x^3`), a special point or bound where `f` is defined when `f` is above its value on each defined side (the one-sided limit, then when equal the sign of the derivative next to it, so jumps count), periodic points by the first non-zero derivative of order 2 to 6 (even order and positive); several variables (`multivariate::local_min`, any `f` `solve_for` handles) by the leading principal minors of the Hessian matrix at the point (`Matrix::det` over `TermSet`, computed symbolically then substituted without expansion and approximated, zero when it vanishes at the maximum precision: all positive is a minimum, alternating from negative a maximum, an invertible indefinite one a saddle), degenerate points and lines of critical points being minima when they are global minima of a rational function without parameters (`f < m` without solution), not when they are global maxima, and an error otherwise. `extrema` / `localextrema` (same arguments, `Optimize::extrema`, `Statement::Extrema`) run both kinds and list the minima then the maxima with the value of `f` (`optimize::Extrema`, printed `min: x = 1, f = -2` one per line, `"min:" x = 1, quad f = -2` in Typst, `no extremum`), integer parameters assumed integer while evaluating.

**Inequalities** (`src/solve/inequality/`). A statement whose comma-separated items include a comparison `<`, `<=`, `>`, `>=`, `!=` (`Parser::parse_items` returns relations, `term/relation.rs::Relation`), or such a `solve(..., x, y)`, is `Statement::Inequalities`, solved by the specialized trait `SolveInequality` (unsupported by default, real impl for `R`) for every symbol sorted by name or the listed unknowns, in that order (other symbols are parameters, unsupported); equations in the system restrict it (`x^2 = 4, x > 0`, `x + y = 1, x != y`). The result is a `Region`: cells with one `Interval` per unknown, whose bounds may depend on the previous unknowns (`x ∈ (-1, 1), y ∈ (-sqrt(1 - x^2), sqrt(1 - x^2))`), printed one line per group of cells differing only by their last interval, which is a union (`x ∈ (-oo, 1) ∪ [2, oo)`, `{0}` for isolated points, `x = 0`, `x ∈ ℝ`, `no solution`, `true`; lines separated by ` \ ` in Typst, `in`, `union`, `RR`). Relations are split into groups sharing no unknown, each one solved by a cylindrical algebraic decomposition (`cad.rs`, at most 3 unknowns and 40 polynomials): numerators and denominators of `lhs - rhs` are factored over ℚ (`Term::factor`, when they have rational coefficients), McCallum's projection (coefficients, discriminants and resultants with `sylvester_determinant`) gives polynomials down to the first unknown, and lifting finds the real roots of each level over a sample point of each cell of the previous levels (`Solve::solve_for` on the substituted polynomial; sectors are sampled at the simplest rational, `simplest`). Signs are exact zeros for the factors whose roots define the cell, else approximations (`approx::approximate`). Over sections, coefficients that approximate a small rational are replaced by it (`rational_value`, also 0), and polynomials of degree 3 or more whose coefficients stay irrational get their roots by elimination (`eliminated_roots`: resultants with the factors vanishing at the sections give a polynomial over ℚ, whose `rootof` roots are kept where the lifted polynomial vanishes numerically), since `solve_for` doesn't finish on coefficients with nested radicals. Bounds are the roots of `solve_for` with the previous unknowns as parameters, matched numerically at the sample (constants when every previous unknown is a point; an unmatched root is an error), and neighboring cells with the same description at the point between them are merged (`x^2 + y^2 <= 1` is one cell). Assumptions on unknowns are more relations, and roots are found without assumptions (`Assumptions::new().enter()`), since `solve_for` drops those contradicting them.

**Assumptions** (`src/context/assumptions/`). `assume(a > 0, b != 0, a > 2*b + 1, n integer)` is a whole statement (`Statement::Assume`, `Parser::parse_assume`; each comparison (`=`, `<`, `<=`, `>`, `>=`, `!=`) is a linear relation between symbols with rational coefficients, both sides read again in `R` and turned into a `LinearForm` by `sign::linear_form`; nonlinear ones and builtin constants are errors; `assume(a)` shows the assumptions mentioning `a`). `Assumptions` holds per symbol bounds, excluded values and an `integer` flag (`Declared`: bounds of integers rounded, `n > 1/2` is `n >= 1`) and relations between several symbols (`LinearRelation`, canonical with coprime integer coefficients), checked for consistency by Fourier-Motzkin elimination over ℚ (`linear.rs`: `feasible`, `signs`; disequalities checked one at a time; integrality only in the per-symbol rounding); the `Assumption` of a symbol (`get`, `assumption`) is derived from all of them: a `SignSet` (bitset of negative / zero / positive, with sign arithmetic for sums and products) plus the `integer` flag; contradicting assumptions are rejected (`this contradicts ...`). They print so that they parse back (`a > b+1`, `2*a > b`). They are stored in the `Environment` (`clear` restores its defaults, `Environment::with_default_assumptions`: sessions start with `Assumptions::defaults()`, `k`, `m`, `n` integers, while `Environment::new()` has none; `dynamic::definitions` (`:defs`) lists those differing from the defaults as an `assume(...)` line, `dynamic::assumptions` (`:assumptions`) every one, marking defaults, `:clear a` removes them) and installed in a thread-local by `Parser::parse` / `parse_statement` when the parser has an environment (`Assumptions::enter`, a guard restoring the previous ones), so parallel tests don't share them and `parse!(input, R)` without environment has none. Everything queries them through `assumption(symbol)` and the sign engine `field/commons/real/sign.rs`: `sign_set(term, mode)` from the structure (values, `pi`, `e`, assumed symbols, sums, products, powers, `exp`, `abs`, odd functions...; sums with a multiple of a symbol having more than a sign condition (`is_relational`) go through `linear_sign`: multiples of symbols are variables of a linear form, other terms variables with their sign, decided by `linear_signs` on the current assumptions, so `abs(a - b) = a - b` for `a > b`; `ln u` takes the sign of `u - 1` likewise, `ln a > 0` for `a > 1`), with `SignMode::STRUCTURAL` (in normalization), `APPROXIMATE` (also approximating constants; `constant_sign` is this) and `GENERIC` (also unassumed parameters non-zero; limits' `const_sign`), and `is_integer`. In `R`: `abs(u)` drops when `u` is non-negative / non-positive (so `sqrt(x^2) = x`, `ln|x| = ln x`), `sign`, `floor` / `ceil` of integers, `(c u)^e` distributes over positive symbols, `sin` / `cos` / `tan` of `u + n pi` with an integer `n` give `(-1)^n`, whose exponent is reduced modulo 2 (`R::reduce_parity`). Integrals use it for `ln` vs `ln|u|` (`integrate::is_positive`), limits for signs of parameters (`lim(exp(a x), x, oo) = oo` with `a > 0`). Calculus builtins (`lim`, `series`, `integrate`, `sum`, `product`) staying unevaluated are split on the values of a parameter (`real/cases.rs`, called from `R::eval_calculus`): the sign engine records the points where it couldn't decide the sign of a symbol or of a linear form in a single symbol (`cases::record`, in `structural_sign`: `a - 1` gives the point 1; sums linear in a single symbol take their sign from `linear_signs`, so `a` inside `a - 1` records nothing; signs at sample points of definite integrals aren't recorded, `cases::unrecorded`), the first parameter among them (by name, not a variable bound in the call or inside it) is split at its points, the open intervals between them assumed (`assume_relation`) and the points substituted, points recorded inside an interval being added and the split done again (at most 4 points), nested for at most 2 parameters, and the values are joined in a flat `piecewise` merged when they agree (a point value never into a branch keeping the call), so `lim(1/(a - 1)^n, n, oo)` with `a > 1` is `piecewise(a < 2, oo, a = 2, 1, 0)` (`integrate(sqrt(r/x - 1), x, 0, r) = pi r/2`, `integrate(exp(a x), x, 0, oo) = piecewise(a < 0, -1/a, oo)`); builtins evaluated inside a split don't split, and a branch staying unevaluated keeps the call, built without normalizing (`cases::normalized_call`, also used by `eval_piecewise`) since normalization evaluates it again; `eval_piecewise` simplifies `piecewise` values with their condition and the negation of the previous ones assumed (when they compare a symbol with 0), so such a call split again collapses, and `definite::inner_integrals` normalizes `piecewise`s in the outer variable with its sign assumed. `solve` drops solutions contradicting assumptions on unknowns (the values of a whole solution substituted in the relations mentioning its unknowns, `linear_expr`) and branches with an equation that can't vanish (specialized trait `Assumed` in `solve/polynomial.rs`, real impl for `R`), inequalities add the relations between unknowns to the CAD, `piecewise` conditions linear in symbols are assumed (`special::sign_condition`), and real roots use assumed signs of discriminants.

**Symbols** (`src/context/`). `Symbol` is a `usize` id interned in a global `RwLock<Context>`; create with `symbol!("x")`. Builtins have fixed ids from `Context::BUILTIN_NAMES`: append new ones at the end, set their arity in `Context::builtin_arity` (one argument by default; checked by the parser), and document them in `context/docs.rs` (`BUILTIN_DOCS`, indexed by id, a test checks every builtin is there: signature, summary, details and examples whose results are written by hand as Typst math), shown by `help <name>` / `help builtins` in sessions and on the documentation page. Builtins are evaluated in the set's `normalize` (e.g. `R::eval_builtin`). In `R`, `cot`, `sec`, `csc` and `log(x, b)` (base 10 by default) are rewritten there with `cos`, `sin` and `ln`, `erfc(x)` as `1 - erf(x)`, `round(x)` as `floor(x + 1/2)` and `trunc(x)` as `sign(x) floor(|x|)` (values directly), so they never survive as functions; `isprime(n)` is 1 or 0 (R and Z); `e^u` is rewritten as `exp(u)`, `exp(u)^c` as `exp(c u)` and products of exponentials as one `exp`; roots of products of positive constants are distributed (`sqrt(2 pi) = sqrt(2) sqrt(pi)`). `asin`, `acos`, `atan`, the hyperbolic functions and their inverses, `erf`, `erfi`, `factorial` and `binomial` stay functions, with exact values at classic points (inverse trigonometric values match radicals by their square, `sqrt(1/3)` like `sqrt(3)/3`; `factorial` of half-integers, `binomial(n, k)` for rational `n`), derivatives (`term/derivative.rs`, also `b^e` with a variable exponent and `integrate(f, t, a, b)` with bounds depending on `x`; none for `binomial`) and approximations. The Gamma family (`real/special.rs`): `gamma`, `polygamma(m, x)` and `zeta` stay functions, `beta(a, b)` is rewritten with `gamma` and `digamma(x)` as `polygamma(0, x)`; exact values of `gamma` at integers and half-integers, of `polygamma` there with the constant `euler_gamma` (Euler-Mascheroni), `ln 2` and `zeta(m + 1)`, and of `zeta` at even and non-positive integers (cached exact Bernoulli numbers, `special::bernoulli`); the builtins `bernoulli(n)` and `euler(n)` are the exact numbers `B_n` (`B_1 = -1/2`) and `E_n` (`special::euler`, cached) for natural `n <= 1000`, printed `B_(n)` / `E_(n)` in Typst, `NumFn::Bernoulli` / `Euler` in f64 for `n <= 400`; derivatives `gamma' = gamma psi`, `factorial' = factorial psi(x + 1)`; approximations by shifting the argument up then asymptotic series (`Fixed::gamma`, `digamma`, `hurwitz_zeta` for `polygamma` and `zeta(s)`, `s > 1`). In Typst they print as `Gamma`, `psi^((m))`, `zeta`, `gamma`. `lambertw(x)` is the principal branch `W_0` (`real/special.rs::eval_lambertw`: `W(0)`, `W(e)`, `W(c e^c) = c` for rational `c >= -1`; derivative `W/(x (1 + W))`, sign of its argument, Newton's iteration in `Fixed::lambert_w`, printed `W` in Typst); `lambertw(x, -1)` is the branch `W_-1`, normalized to the internal one-argument function `@lambertwm1` (`Context::lambertw_m1`, so that `unary` sees it; `lambertw(x, 0)` is `W_0`, other branches stay unevaluated): `W_-1(c e^c) = c` for rational `c <= -1`, negative, same derivative, Newton's iteration kept below `-1`, `NumFn::LambertWm1`, printed `lambertw(x, -1)`, `W_(-1)(x)` in Typst and `W₋₁` pretty. `piecewise(c1, v1, c2, v2, ..., default)` (`special.rs::eval_piecewise`): the parser accepts comparisons only as its conditions (`Parser::parse_piecewise_args`), stored as internal functions `@lt(lhs, rhs)`, `@le`, `@gt`, `@ge`, `@eq`, `@ne` (`term/relation.rs::Relation`, printed `lhs < rhs`); conditions are decided by `sign_set(lhs - rhs, APPROXIMATE)`, false ones dropped, a leading true one gives its value, none left gives the default or `undefined`; derivatives are taken branch-wise, Typst prints `cases(...)`. `diff(f, x, n)` is the `n`-th derivative (`fun::eval_calculus_builtin`). `subs(f, x, a)`, `numer(f)`, `denom(f)` (`as_fraction`), `resultant(p, q, x)` and `discriminant(p, x)` (variable optional for a single symbol; `sylvester_determinant` on `polynomial_form`, degrees adding up to at most 14) work in every ring (`fun::eval_algebra_builtin`; in `R`, `subs` also substitutes in exponents with `expr::subs`). The sine, cosine and exponential integrals `Si`, `Ci` (for positive arguments) and `Ei` stay functions: values at 0 and `±oo`, `Si` odd with the sign of its argument, derivatives `sin(u)/u`, `cos(u)/u`, `e^u/u`, approximations by power series with extra bits, or asymptotic series for large arguments (`Fixed::exponential_integral`), and f64 / WGSL forms for graphs. `apart(f, x)` (variable optional when `f` has a single symbol) is the partial fraction decomposition over ℚ, and over ℚ(i) in `C` (`integrate/apart.rs`, `Term::apart`, generic over the dense coefficients through `poly.rs::TermCoefficient`, implemented by `Rational` and Gaussian `[Rational; 2]`, factors from `Term::factor`: per irreducible `q^e` of the denominator, the numerator by `inverse_mod` of the cofactor, then its `q`-adic digits), unevaluated for symbolic coefficients. `degree(f, x)` (variable optional likewise; `fun::eval_degree`, in R, C, Z, Zn and `Poly`) is the degree of the expanded polynomial, coefficients assumed non-zero, unevaluated for `0`, non-polynomials and degrees that aren't natural numbers of the set (`7` in `Z/7`); in `R`, exponents that are non-negative integers by the assumptions are allowed, giving the `max` of the exponents not dominated by another one (`max(10, n)` for `x^n + x^10`, `R::eval_degree`). Odd and even functions take the sign out of their argument (`sin(-u) = -sin(u)`, `cos(-u) = cos(u)`), `sin`, `cos`, `tan` of `u + q pi` reduce `q` (quarter turns for half-integers, else into `(-1/2, 1/2)`), and have radical values at multiples of `pi/12`, `pi/10` and `pi/8` (`eval_trig_at_pi_multiple`, `tan` from its own table so that radicals stay out of denominators, `tan(pi/12) = 2 - sqrt(3)`); `atan` of a half-angle form in the sine and cosine of a single constant angle `a` is the angle reduced into `(-pi/2, pi/2)` (`eval_atan_half_angle`: `(1 ± sin a)/cos a = tan(pi/4 ± a/2)`, `sin a/(1 + cos a) = tan(a/2)`... compared by expanding cross products, so `sin(x + 1) = cos(x)` gives `x = pi/4 - 1/2 + pi k`); `ln(q) = -ln(1/q)` for `0 < q < 1`; `exp(q ln c) = c^q` for rational `q` and a positive value `c`; `(c u)^e = c^e u^e` when `c^e` is rational (`sqrt(4 x^2) = 2|x|`), roots of odd order take the sign out of products with a negative coefficient and of sums of negative terms (`(-x)^(1/3) = -x^(1/3)`, so limits at `-oo` see real odd roots), `sqrt(a + b sqrt(c))` is denested when possible, and `(k ± k cos a)^(m/2) = (2k)^(m/2) |cos(a/2)|^m` (`|sin(a/2)|^m`) for a constant angle `a`, the sign being approximated (`R::half_angle_root`, `sqrt(2 + 2 cos 1) = 2 cos(1/2)`). In sums, `c M sin(u)^2 + c M cos(u)^2 = c M` for any `u` and the same other factors `M` (`R::pythagorean`). Constant radical sums (rational multiples of products of roots of positive values, `real/radicals.rs`) have a single form, computed in the tower `ℚ[y_1, ..., y_n]/(y_k^(q_k) - b_k)` of their radicals (`radicals::Tower`, like `holonomic/algebraic.rs` over ℚ, dimension at most 64): one generator per group of primes whose exponents in the value bases are proportional (`sqrt(2) + 3^(1/3)` has the generators 2 and 3, `6^(1/64)` the generator 6; coprime and not perfect powers, so their monomials are independent and the form canonical), and one per nested root `s^(p/q)` of a positive radical sum `s`, inner ones first (an inverse found in the tower is right even when it isn't a field, evaluation being a ring homomorphism; none when it is a zero divisor). Negative integer powers are rationalized there (`radicals::power`, inverse by `solve_linear_unique` on the multiplication matrix: `1/(sqrt(2) + 3^(1/3))`, `1/(1 + sqrt(2 + sqrt(2)))`), positive powers and products of such sums with other radicals (not nested ones, which made Ferrari's roots too slow) are expanded (`radicals::expand_product`, in the tower, or term by term up to 256 terms when it is too big), and the rational content of a radical sum factor moves to the coefficient of its product (`(8 - 4 sqrt(3))/4 = 2 - sqrt(3)`, `x (1 + sqrt(3))^2 = 2 (sqrt(3) + 2) x`, a lone `-1` being distributed), so `1/(1 + sqrt(2)) = sqrt(2) - 1` and `(sqrt(6) - sqrt(2))/(sqrt(6) + sqrt(2)) = 2 - sqrt(3)`. Cardano's formula writes its second cube root `v = -p/(3u)` so both live in the tower of `u`, and `expand` writes sums with nested roots in their tower (`radicals::canonical_sum`; in `C` through their parts), so zero tests by expansion hold for its roots (`2 u^2 - c/u = 0` for `u = c^(1/3)`). `pi`, `e`, `euler_gamma`, `oo` (infinity) and `undefined` (a limit that doesn't exist) are builtin constants (`Context::is_builtin_constant`, arity `(0, 0)`): symbols that can't be defined and aren't unknowns of `solve`. Terms with `oo` factors are never merged by the generic normalization (`Term::is_infinity_factor`), and `0 oo` is `undefined`; `R::eval_infinite` does the rest: `oo - oo` is `undefined`, finite constants are dropped from sums with `oo` (symbols are kept, `x + oo`), products with positive constants and positive powers are `oo`, `oo^-n = 0`, and `undefined` absorbs sums and products. Functions have their limits as values at `oo` (`exp(-oo) = 0`, `atan(oo) = pi/2`). The builtins `expand` and `simplify` do more in `R` than internal expansions (`real/rewrite.rs`): addition formulas for `sin` / `cos`, and for `simplify` the smaller of the plain simplification and that of the term rewritten with `exp(c ln u) = u^c` (`expr::exp_of_ln`, not a normalization rule since limits and integrals build `exp(g ln b)`), integer quotients of logarithms, hyperbolic functions as `exp`, multiple angles and `sin^2 = 1 - cos^2`, or the expansion of the term with its products of `sin` and `cos` written as sums (`products_to_sums`, up to 8 factors: `cos(2x) cos(3x) + sin(2x) sin(3x) = cos x`), whichever is smaller.

**Approximation** (`src/field/commons/real/approx.rs`). `approx(x, digits)` (15 significant digits by default) evaluates the numerical parts of an `R` expression with fixed-point integer arithmetic (`exp`, `ln`, `sin`, `cos`, `tan`, roots, `pi`, `e`; other builtins are normalized on approximated arguments), raising the working precision until the result has enough significant bits, then rounds to an exact `Rational` (`exp` of negative arguments as `1/exp(-x)` and `W_-1` by Newton's iteration on `w + ln(-w) = ln(-x)`, keeping the relative precision of tiny values). `pi` and `ln 2` are cached per thread and precision (`Fixed::cached`), since the terms of sums and integrals use them again and again. Results carry the `APPROXIMATE` flag (`term/flags.rs`, on a `Value`, or on a `Mul` for its coefficient), printed as decimals through `Set::print_approximate`. The flag is contagious when constants are merged (`Term::try_merge_terms` / `try_merge_factors`, `Mul` normalization), and powers or builtins of approximated values are approximated in `R::normalize`; other rewrites may drop it.

**Limits** (`src/limit/`). `lim(f, x, a)`, or `lim(f, x, a, 1)` / `lim(f, x, a, -1)` for right / left limits, is evaluated in `R::normalize` through `Term::limit` (`R` only; it evaluates to `undefined` when the limit doesn't exist, and stays unevaluated when it is unsupported or unknown, see `LimitError`). `floor(g)` / `ceil(g)` are first replaced by their constant value near the point (`remove_steps`, from `lim g`, and at an integer from the sign of `g - n` on each side). Powers with an exponent depending on `x` are then rewritten as `exp(g ln b)` (`|b|^g cos(pi g)` for a negative constant `b` at `±oo`, unsupported at finite points and for a constant `b` not known to be positive), `tan` as `sin / cos`, `sign(u)` as `u / |u|`, `min` / `max` with `abs`, hyperbolic functions and their inverses with `exp` / `ln`, `asin` / `acos` with `atan`, and `factorial` / `binomial` with `gamma` (`exp_log_form`), so `atan` is the only inverse function the series engine handles (`atan a = ±pi/2 - atan(1/a)` at infinity). `erf` has a Taylor series at finite points (Hermite polynomials, also `erfi`); `erf g` with `g -> ±oo` is rewritten as `±(1 - exp(-g^2) erfcx(±g))` before `mrv` (`erf_at_infinity`), and `erfi g` as `±exp(g^2) erfix(±g)`, the internal `@erfcx` and `@erfix` having asymptotic series in `1/g`. `Ei g` with `|g| -> oo` is `exp(g) @eistar(g)`, and `remove_oscillations` writes `Si g` / `Ci g` with `|g| -> oo` (`Ci` at `+oo` only) as `±pi/2 - @sif(g) cos t - @sig(g) sin t` and `@sif(g) sin t - @sig(g) cos t` with an angle `t`, the auxiliary functions having asymptotic series; at finite points the series engine uses their power series at 0 and their Taylor series from derivatives elsewhere. Likewise `gamma g` with `g -> oo` is rewritten by Stirling's formula `exp((g - 1/2) ln g - g + ln(2 pi)/2 + @lgammastar(g))` (`special_at_infinity`); with `g -> -oo`, `Gruntz::limit` first applies the reflection formula `gamma g = pi/(sin(pi g) gamma(1 - g))` (`reflect_gamma`), so `sin(pi g)` gets an angle (nested in internal limits it stays unsupported). The series engine expands `gamma` and `polygamma` at finite points (`gamma(a0 + u) = gamma(a0) exp(sum psi^(j-1)(a0) u^j / j!)`, Laurent series at poles through the recurrence) and `polygamma(m, g)` at `+oo` by its asymptotic series. At a finite point, `f` is evaluated directly when no singularity is met (`eval_at`), otherwise every limit is reduced to `x -> +oo` (`x -> a + 1/x`, `a - 1/x`, `-x`; two-sided limits compute both sides). There, the Gruntz algorithm (`gruntz.rs`) takes the most rapidly varying subexpressions (`mrv`, `x` or exponentials, moved up with `x -> exp(x)` when `x` is one of them), rewrites them as `A w^c` with `w -> 0^+` (`rewrite`, `ln w` becoming an expression in `x`), and takes the leading term `c0 w^e0` of a truncated series in `w` (`series.rs`: exponents are constant terms, possibly irrational like `ln 2 / ln 3`, compared numerically; coefficients may contain `x`; absolute orders are raised until a non-zero leading coefficient is found). The limit is 0, `±oo` by the sign of `c0`, or the limit of `c0`. Zero tests simplify, then approximate (constants) or evaluate at a few rational points (coefficients in `x` and angles); other parameters are assumed non-zero unless assumed otherwise (signs of constants go through the sign engine, see Assumptions). The entry point `Gruntz::limit` adds, around the internal `limit_infinity`: `sin g` / `cos g` with `|g| -> oo` (a negative exponent of the leading term of `g`, so the sign of a parameter like `t` in `cos(t x)` doesn't matter) get an angle `@t<n>` in place of `g` (a constant for the algorithm, linked as `k t + d` to an earlier angle when `g ~ k g_t + d`, `remove_oscillations`); `check_bounded` requires every division, `ln` or root of a term with angles to stay away from 0 (interval arithmetic in `bounds.rs`), else `Unknown`, or `Undefined` when the poles accumulate (`accumulating_poles`: a factor `sin(u)^n` / `cos(u)^n` of the denominator with `u` linear in an angle, the rest not vanishing at its zeros for large `x`, and `n` odd or the rest with a finite limit, so `gamma(x)` at `-oo` and `tan x` at `oo` are `undefined` but `x/sin(x)^2` stays unevaluated); a result depending on a single angle is `Undefined`, a constant one (checked at sample angles with `approximate_fixed`) is kept; an infinite limit whose sign depends on parameters is `sign(a)*oo` (only at the top level, internal limits only use exact `±oo`). Two-sided limits are `Undefined` only when both sides surely differ. Recursion is bounded (`MAX_DEPTH`).

**Series** (`src/limit/expansion.rs`). `series(f, x, a, n)` (default `n = 6`, optional side `1` / `-1` like `lim`) gives the terms of `f` below `(x - a)^n` (below `x^-n` at `±oo`), evaluated in `R::normalize` through `Term::series` (without the remainder), plus the remainder `o((x - a)^(n - 1))` (`o(x^(1 - n))` at `±oo`, `limit::remainder`, also added in `C`). `o(u)` is a builtin staying a function: `R::normalize` absorbs constant factors (`o(-2 u) = o(u)`, so `o(u) - o(u) = o(u)`) and moves products inside (`f o(u) = o(f u)`); sums of `o` terms aren't merged, since which one dominates depends on the point. Sums print `o` terms last (`Add::print_order`), it has no derivative, and `Numeric` compiles it as 0 so truncated series can be drawn. It substitutes `x -> a ± w` (`±1/w` at `±oo`), runs the Gruntz series engine (`series::expand`, `w -> 0^+`, `ln w` as a placeholder replaced by `ln(x - a)`), and substitutes back (`ln w` as `-ln(s x)` at `s oo`). Exponents may be negative or fractional. Two-sided series compute both sides and must agree (`abs(x)`, `sqrt(x)` at 0 stay unevaluated); non power series (`exp(x)` at `oo`, `exp(1/x)` at 0) stay unevaluated. `series(f, x, a, oo)` (`sum/taylor.rs`, `Term::infinite_series`) is the whole series, every general term being proven. Holonomic functions first (`src/holonomic/`): `dfinite::annihilator` derives a linear differential equation of `f w^(-e_0)` in `w` (after `x = a ± w` or `±1/w`) by closure rules (rational functions, `exp`, `sin`, `cos`, `sinh`, `cosh` of rational arguments, constant powers of order-1 functions with an analytic non-zero base when not integers, algebraic functions (`holonomic/algebraic.rs`: rational powers of rational functions, possibly nested, with analytic non-zero bases, computed in the tower `K(w)[y_k]/(y_k^(q_k) - b_k)` with the derivation `D y_k = D(b_k)/(q_k b_k) y_k`, the derivatives of `f` reduced there until a linear dependency; bases depending on `w` first split into their factors over ℚ, `b^r = c^r ∏ g_i^(e_i r)` with `g_i(0) > 0`, `split_bases`, so related bases share their generators, and roots of positive rationals are generators with a zero derivation; dimension at most 64), `atan`, `asin`, `acos`, the inverse hyperbolic functions, `ln`, `erf`, `erfi`, `Si` as integrals, sums by LCLM, products by symmetric product; `ore.rs`: `Operator` over `ratfun::RatFun`, rational functions with `Elem` coefficients implementing `Coefficient`, `annihilator` finding the first linear dependency, at most order 8), `recurrence::Recurrence::from_differential` turns it into the recurrence of the coefficients, whose initial values (the first ones and those after natural roots of the leading coefficient, `ratfun::natural_roots`) come from the series engine (`limit::series_terms`), giving 64 proven coefficients `c_j` of `w^(e_0 + j)` in `QQ(t_1, ..., t_n)` (`sum::field::Params`). Otherwise (no rule, Puiseux exponents) about 30 coefficients come from the series engine. A recurrence `P(n) c_(n + m) = Q(n) c_n` of least period `m <= 4` and degree `d <= 4` is guessed (`P` monic, unique solution by `fraction::solve_linear_unique`, at least 8 more non-trivial equations than unknowns, valid from `n >= 2` and possibly earlier), then proven: `Recurrence::proves` finds the recurrence of `d_n = P(n) c_(n + m) - Q(n) c_n` by reducing its shifts and checks `d_n = 0` up to past its singular indices; without the holonomic route, `verify_by_ode` checks `P(θ - m)(g - h_0) = t^m Q(θ) g` on the tail `g` of `f` (`θ = t d/dt`, `t = w^(1/q)`), rejected numerically at sample points, `t` assumed positive, proven zero in the tower of its radicals (`algebraic::is_zero`: zero there means identically zero), by `expand` or by `simplify` below 80 nodes, undecided being rejected. When no two-term recurrence is found, the recurrence of a holonomic function with rational coefficients goes to Petkovšek's *Hyper* (`holonomic/hyper.rs`: `A` and `B` products of the rational linear factors of `P_0(n)` and `P_r(n - r + 1)`, at most 6, `Z` rational or Gaussian, roots of the leading coefficients, `C` a polynomial solution of degree at most 6 over `QQ(i)`; `hyper_series` fits `c_n = Σ α_i h_i(n)` from an index past the natural roots of `P_r` and the roots of `A` and `B`, which proves it, conjugate pairs written `2|Z|^n (Re D cos(nθ) - Im D sin(nθ))`), so `exp(x) cosh(2x)` is a single sum of `(3^k + (-1)^k)/(2 k!) x^k`. Each residue class is `c_i` times a `Term::product` of `Q/P`, indexed by the exponent when `m = q = 1`, else `n = m k + i`; tidied with the duplication formula (`product::duplicate_gammas`), half-integer `Gamma` as factorials, `binomial`, split and absorbed powers of values (then merged, `4^k` rather than `2^(2k)`), cleared denominators. Failing that, rational functions are split by `apart`, products expanded (`(x + 1) atan x`) and sums term by term, their rational terms by `apart` too (kept when they give fewer sums than the whole, held sums whose terms differ by a factor free of `x` merged; with parameters, the guess is first tried at a rational point of them, `consistent_at_sample`, since it is slow over `QQ(t)` without solution), and rational functions with rational coefficients go to `rational_series` (for square-free denominators whose irreducible factors over ℚ have real roots or are of degree 2, `simple_poles`: `B ρ^k` per real root `ρ` of the reversed factor, `real_poles`, `eigen::real_roots`, coefficients rationalized against `a + b sqrt(c)`, Binet's formula for `1/(1 - x - x^2)`; `r^k (a cos(kθ) + β sin(kθ))` per quadratic factor `1 - p w + s w^2`, its part `(a + b w)/q` of the partial fractions by `inverse_mod`, `r = sqrt(s)`, `θ = expr::arg(p/2, sqrt(4s - p^2)/2)`, so `1/(1 - x + 2x^2)` has `cos(k atan(sqrt 7))`; first coefficients by dividing the power series, `power_series`; otherwise `general_poles`: per irreducible factor `q` of multiplicity `e`, `Σ_(l<e) n^l Σ_ρ A_l(ρ) ρ^n` over the roots `ρ` of the reversed `q`, the rational coefficients of `A_l` solving a linear system on the first coefficients through the power sums of `q` (`power_sums`, Newton's identities), the roots by radicals in `C` or else the real ones as `rootof` and a single pair of complex roots from Vieta's formulas, `root_parts`, a pair `u ± i v` giving `2|ρ|^n (Re A_l cos(nθ) - Im A_l sin(nθ))`). Algebraic functions which are polynomials (a derivative of order at most 5 is zero in the tower, `algebraic_polynomial`, like `sqrt(2 + 2x)/sqrt(1 + x) = sqrt(2)`) are their Taylor polynomial. Before all that, `known_series` matches `C w^m K(α w)` for kernels whose coefficients are Bernoulli or Euler numbers (`Kernel`: `tan`, `tanh`, `1/cos`, `1/cosh`, `1/sin`, `1/sinh`, `cot` as `cos/sin` or `1/tan`, `coth`, `1/(b e^t - b)`), with general terms in `bernoulli(2k)` / `euler(2k)`. At a regular point `t = β + α w` (`β != 0`, not a pole), `tan`, `cot`, `1/cos` and `1/sin` use their partial fractions (Mittag-Leffler, `shifted_kernel`): `cot(β + u) = Σ c_n u^n`, `c_n = -(ψ^(n)(q) + (-1)^(n+1) ψ^(n)(1 - q))/(n! π^(n+1))`, `q = β/π`, the others by shifts and `1/sin z = Σ (-1)^m/(z - m π)`. Powers `K^n` (`2 <= n <= 6`) of `tan`, `tanh`, `cot`, `coth`, and even powers of `1/cos`, `1/sin` and their hyperbolic versions written with them, come from the Riccati equations `K' = p + q K^2` (`kernel_power`, finite points from the right, the series differentiated term by term), and a kernel times other factors is the Cauchy product of its series and theirs (`product_series`, `multiply_series`: polynomials in `w` as their terms, explicit terms moved into the sums, two sums `Σ A(k) w^(αk + β)` (`α` 1 or 2) and `Σ B(k) w^(k + δ)` giving a held sum of finite sums `sum(A(j) B(N - αj), j, a, floor((N - b)/α))`, evaluated by `Fixed::finite_sum` and `Numeric::FiniteSum`). Constants move into held sums and leading terms cancelled by explicit terms are dropped (`scale_held_sums`, `cancel_leading_terms`); `merge_sums` merges sums whose starts differ by at most 4, the first terms of the earlier one made explicit. The sums are held: the internal function `@sum` (`Context::held_sum`, printed like `sum`, so the printed text parses back to a `sum`) isn't evaluated, since `sum(x^k/k!, k, 0, oo)` would give `exp(x)` back. Held sums are differentiated term by term (`Derivable::derivative_function`, the hook of set-specific derivatives, `derive_held_sum`) and integrated term by term when the general term is `C(k) B^E` with `B` linear in `x` and `E` affine in `k` (`integrate_held_sum`, called by the `Integrator`, which also moves other factors depending on `x` into the terms, `held_sum_product`; the terms with `E = -1` integrated separately, giving logarithms), or another term with such a factor and `E` increasing, integrated with a symbolic natural `k` as `G(x, k) - G(x_0, k)`, `B(x_0) = 0`; definite integrals evaluate the held sums of the antiderivative at the bounds when the ratio test proves they converge there (`definite::held_sums_at_bounds`, `held_sum_at` / `held_sum_between`, zero at the root of `B`), the rest as usual, and keep their held sums unexpanded. Both are re-indexed by the exponent of `B` when `E = ±k + c` and their leading zero terms dropped (`tidy_held_sum`, denominators of general terms factored, `factor_denominators`); `has_special_constant` skips their bound `oo`. `approx` adds their terms until 8 consecutive ones are below the precision (`Fixed::infinite_sum`, at most 1000 terms, terms bound without normalization, factorials of naturals exact; a term with held sums is zero below `2^(-4 needed)` bits instead of raising the precision to its maximum, `has_held_sum`), and `Numeric::Sum` likewise in f64 (at most 2000 terms, NaN when a term has a non-finite part, like an overflowing `(2k)!` outside of the disk of convergence; on the GPU a bounded loop in f32, `Emitter::sum` in `shader.rs` with the index mapped to the loop variable, Bernoulli and Euler numbers from f32 tables, `nf_bernoulli_number` / `nf_euler_number`, NaN beyond their range; products in the loop multiply mantissas and exponents separately, `Emitter::scaled_product`, and a term overflowing after negligible ones ends the sum), so whole series are drawn; `numeric::free_symbols` leaves their index out of graph parameters. Recurrences without a two-term form (`x e^(x^2) cos x`) and denominators with several pairs of complex roots that `C` can't find stay unevaluated.

**Integration** (`src/integrate/`). `integrate(f, x)` and `integrate(f, x, a, b)` are evaluated in `R::normalize` through `Term::integrate` / `Term::integrate_definite` (`R` only; unevaluated when no antiderivative is found, `oo` / `-oo` / `undefined` for divergent definite integrals, see `IntegrateError`). `Integrator` (`mod.rs`) is a recursive search bounded by `MAX_DEPTH`, caching results by `(variable, integrand)`, substitution variables being `@i<depth>`: rational functions of `x` with rational coefficients go to `rational.rs` (always, dense `Poly` over ℚ (`polynom/dense.rs`, shared with the univariate factorization; `poly.rs` converts terms): polynomial part, Hermite reduction, then per irreducible factor `q` of the square-free denominator the residue polynomial `p = A D'^-1 mod q`, a constant giving `c ln|q|`, otherwise roots of `q` in `C` by radicals (`PolynomialRoots`, `split_complex` in `solve/polynomial.rs`) giving `ln|x - r|` for real roots and `ln` + `atan` for conjugate pairs; `None` when the roots can't be computed). Other integrands: sums term by term, constant factors out, square roots merged (`sqrt(u) sqrt(v) = sqrt(u v)`, which holds where the integrand is real) and factors depending on `x` common to the terms of a power of a sum pulled out, then the first strategy that succeeds among `table.rs` (functions of linear arguments including `erf` / `erfi`, `1/(A x^2 + B)` with symbolic `A`, `B` as `atan`, square roots of quadratics, `e^u sin v`, `p e^q` for polynomials `p` and quadratic `q` with `erf` / `erfi`, products of exponentials merged, `g(a x + b)/(p x + q)` for `g` = `exp`, `sin`, `cos` with `Ei`, `Si`, `Ci`), `trig.rs` powers (`sin^m cos^n` with `t = cos`, `sin` or `tan`, or power reduction), `substitution.rs` (derivative-divides on subexpressions, `replace` also maps `b^q` to `t^(q/p)` and `exp(c)` to `t^(c/a)`; `b = exp(t)` for `u = ln b`, results go through `exp_of_ln`; linear `u` also substitutes `x`, not again in a variable coming from such a substitution), `trig::substitute` (rational functions of `x` and `sqrt(q)`, `q = a u^2 + k` quadratic with rational coefficients: `u = r sin t`, `r / cos t` (for `u > r`) or `r tan t`, the result in `t` written back with `sqrt(q)` after mapping `sin(n t)`, `cos(n t)`, `tan(t/2)`; rejected when it grows too much; it runs inside `algebraic.rs`, which keeps the smaller of it and Euler's substitutions `t = sqrt(q)/(x - alpha)` for a rational root `alpha`, `t = sqrt(q) + sqrt(A) x`, `t = (sqrt(q) - sqrt(C))/x`, or `t = sqrt(q/A) + x`, and before them rationalizes rational functions of `x` and of powers `y^(p_i/q_i)` of a single Möbius function `y = (a x + b)/(c x + d)` with `t = y^(1/L)`, `L` the lcm of the `q_i`, so `integrate(sqrt(1/x - 1), x) = x sqrt(1/x - 1) - atan(sqrt(1/x - 1))`), `parts.rs` (logarithms and inverse functions, then polynomial factors), `trig.rs` rewrites (hyperbolic functions as `exp`, product-to-sum, also merging factors of the same argument and reducing powers when the product has a non-trigonometric factor, so `e^x sin x cos x` becomes terms of `table.rs`'s `e^u sin v`, Weierstrass `t = tan(u/2)`), then the Risch algorithm (`risch/`), and finally the expanded integrand. When the search fails, `abs` / `sign` of terms depending on `x` with finitely many real zeros (`abs.rs`) are replaced by `±u` / `±1` on each interval between the zeros, whose antiderivatives are joined continuously: with `sign(u)` for a single zero (and with `|u|` for a linear `u` when the pieces agree up to the sign, `integrate(exp(-|x|), x) = sign(x) (1 - exp(-|x|))`), with `piecewise(x < x_1, ..., x < x_n, ...)` otherwise. The Risch algorithm (transcendental case, Bronstein) writes the integrand in a tower `QQ(x, t_2, ..., t_n)` of `exp` / `ln` monomials (`tower.rs`: `b^g` as `exp(g ln b)`, hyperbolic functions as `exp`; a new monomial is checked against the Risch structure theorems by evaluating at sample points and solving over ℚ, dependent ones are written with existing monomials, rebuilding with `exp(b/q)` first when `exp(a)` is a non-integer power of `exp(b)`; other functions, roots and symbols are unsupported). Elements (`polynom/fraction.rs`) are canonical nested fractions of dense `Poly<Elem>` (`polynom/dense.rs` is generic over `Coefficient`). Integration in `K(t)` (`mod.rs`): Hermite reduction with the derivation, Rothstein-Trager residues (resultant interpolated in `z`; non-constant residues prove non-elementarity, irrational ones above `QQ(x)` are unsupported), then the polynomial part: limited integration of coefficients for `ln`, Risch differential equations (`rde.rs`: weak normalization, normal / special denominators, degree bounds, SPDE, non-cancellation and recursive cancellation cases) for `exp`. Undecided steps are `RischError::Unsupported`, so `IntegrateError::NonElementary` (returned by `Term::integrate`, the integral stays unevaluated) is a proof. Substitutions `b = t^(1/p)` for `u = b^p` are only done for integer ratios or positive `b`. Logarithms are `ln|u|` unless `u` is provably positive (`is_positive`). Definite integrals (`definite.rs`) on `[0, oo)` first try Mellin-type integrals (`mellin`: `x^(s-1)` times `e^(-c x)` gives `gamma(s)/c^s`, times `1/(e^(c x) - 1)` gives `gamma(s) zeta(s)/c^s`, times `1/(e^(c x) + 1)` with the factor `1 - 2^(1-s)`). Then they replace sums and functions of inverse trigonometric functions that are constant on the open interval by their value (`constant_parts`: no singular point inside, and the derivative is exactly zero once square roots of squares of rational functions are written with their sign on the interval; evaluated at a point with exact values when possible), and on finite symmetric intervals `[-b, b]` integrate `f(x) + f(-x)` on `[0, b]` when it is a rational function in the Risch tower and `f` is not (`1/(e^x + 1) + 1/(e^-x + 1) = 1`, odd functions give 0; `f` must be continuous). With `abs` / `sign` of terms depending on `x`, the interval is first cut at the zeros of their arguments (`split_abs`, `zeros`), each piece being integrated with `|u| = ±u` by the sign at an interior point (`integrate(exp(-|x|), x, -oo, oo) = 2`). They then split `[a, b]` at the singular points of `f` and `F` (real roots of polynomial denominators, zeros of `sin` / `cos` in denominators, poles of `tan`; other denominators are sampled for a sign change, else `Unsupported`) and sum one-sided `Term::limit`s of `F`; at regular bounds the substituted value is preferred when it agrees numerically (limits rewrite `tan`). With symbolic bounds (`definite::symbolic`), the denominators, `ln` arguments and fractional power bases of `f` and `F` (`critical_factors`, other non-continuous parts are unsupported) must have a strict sign (with the sign of the variable between the bounds assumed, and `a < x < b` when the bounds are linear in symbols with a known order, `between`), or be linear with a root outside of the interval or at a bound (then a one-sided limit). Iterated integrals: an unevaluated inner definite integral depending on the outer variable `x` is evaluated again (`inner_integrals`) with `x`'s sign on `(a, b)` assumed and, for numeric bounds, its range pushed on a thread-local stack used by `range_sign` (the sign engine, else for a term in a single ranged variable its zeros there and a sample point; `same_sign` uses it too). `split_constant` splits `exp(u + v)` with `u` free of `x`. Definite results are the smaller of the result and its expansion. `approx(integrate(f, x, a, b))` uses double exponential quadrature in `Fixed::integrate` (`approx.rs`: tanh-sinh, exp-sinh, sinh-sinh by the bounds), halving the step until two results agree to half the precision; nodes are bound without normalization (`bind`).

**Sums and products** (`src/sum/`). `sum(f, k, a, b)` and `product(f, k, a, b)` (arity 4, bounds may be `-oo` / `oo`) are evaluated in `R::normalize` through `Term::sum` / `Term::product` (`R` only; `SumError::Divergent` gives `±oo`, `Undefined` gives `undefined`, `Unsupported` leaves them unevaluated). Integer value bounds with at most 100 terms are computed term by term (`expr::subs`, which also substitutes in exponents), so are larger ranges up to 1000 terms when no closed form is found. Otherwise an antidifference `F` (`F(k + 1) - F(k) = f(k)`, `mod.rs::antidifference`) gives `F(b + 1) - F(a)`, the first strategy that succeeds among: constant factors out, `binomial(u, m)` with a small natural `m` expanded as a polynomial, polynomials in `k` by Faulhaber's formula (`polynomial.rs`, Bernoulli numbers from `special::bernoulli`), geometric terms `r^k p(k)` (`r != 1` assumed), Gosper's algorithm (`gosper.rs`: the ratio `t(k + 1)/t(k)` built structurally from rational functions, `c^(alpha k + beta)`, `exp`, `factorial` / `gamma` / `binomial` of linear arguments with integer slopes; Gosper form with the shifts found as natural roots of a resultant computed with the parameters specialized at sample points, then checked exactly; key equation solved by undetermined coefficients with a degree bound), rational functions over ℚ whose denominator has rational roots as `polygamma` (`sum(1/k, k, 1, n) = psi(n + 1) + euler_gamma`), then sums term by term. Coefficients are in `QQ(t_1, ..., t_n)` (`field.rs::Params`), every maximal subterm free of `k` being a generator, using the nested fractions `Elem` of `polynom/fraction.rs` (shared with the Risch algorithm, with `interpolate`, `sample_points` and `solve_linear`). Values at a removable singularity of `F` and infinite bounds are limits (`mod.rs::limit`, over a fresh real variable `@k` not assumed integer, with `c^g` for a negative `c` rewritten as `|c|^g cos(pi g)`, also at removable singularities where `k` is an integer); the computation runs with `k` assumed integer. Infinite sums without antidifference try known series (`zeta(s)` for `k^(-s)`, `exp(x)` for `x^k / k!`). Products use an antiquotient `G` (`product.rs`): `c^k`, multiplicative over factors and constant powers, `c^g` as `c^(antidifference g)`, linear factors `alpha k + beta` as `alpha^k gamma(k + beta/alpha)` (a factorial when `beta/alpha` is an integer), polynomials with rational roots; `G(b + 1)/G(a)` (unsupported at poles), then `combine_factorials` merges factorials whose arguments differ by integers (`(n + 1)!/n! = n + 1`, `u/u! = 1/(u - 1)!`). Results are tidied (`mod.rs::tidy`: smallest of the result, its expansion, and for rational functions its simplification and factorization; `simplify` may not terminate on other terms). Typst prints `sum_(k = a)^(b) f`, the pretty printer a `∑` / `∏` column (`PrettyPrinter::big_operator`).

**Differential equations** (`src/ode/`). `dsolve(y' = x*y)`, `dsolve(y'' + y = 0, y(0) = 1, y'(0) = 0)` or `dsolve(diff(y(t), t) = t, y, t)` is a whole statement (`Statement::Ode`, `Parser::parse_dsolve`; builtin `dsolve`, the lexer's `'` token `TokenKind::Prime` is only accepted there). Trailing identifier arguments name the function and the variable, otherwise the function is the first identifier followed by `'` (else called like a function) and the variable its symbol argument, or `x`. Arguments `y'(a) = b` with `a` not the variable are initial conditions (`Condition`), the single other one the equation, parsed with `Parser::with_ode`: `y`, `y(x)` and `y''` become `y(x)` and unevaluated nested `diff(y(x), x)`. The `Dsolve` trait is specialized (unsupported by default, real impl for `R`); it replaces `y(x)` and its derivatives by placeholders `@y0, @y1, ...` (`y` elsewhere is unsupported). First order (`first_order.rs`): `e = 0` is solved for `@y1` with `Solve::solve_for`, each slope `F(x, y)` is linear (`dF/dy` free of `y`, integrating factor `exp(-integrate(a))`, `ln|u|` written `ln u` there since only a constant factor matters) or separable (factors free of `y` / of `x`, `exp` of sums split, `Term::factor` for rational functions), `G(y) = H(x) + c` being inverted for sums of rational multiples of logarithms (`p(y) = c exp(d H)`, the constant absorbing the sign), `alpha exp(u(y))`, or by `solve_for`, and kept implicit (`OdeBranch::Implicit`) otherwise; the roots of the factor `q(y)` of a separable slope `p(x) q(y)` are added as constant solutions unless a solution with `c = 0` already gives them. Higher orders (`linear.rs`) need constant rational coefficients: characteristic polynomial as a dense `Poly`, square-free parts for multiplicities, `rational::factor` then `PolynomialRoots` in `C` split with `rational::split` (`x^j exp(u x)`, with `cos(v x)` / `sin(v x)` for `u ± i v`), and a particular solution by variation of parameters (Wronskian system solved with `solve_for`, `u_i'` simplified then integrated, terms proportional to the basis dropped). Constants are `c_1, c_2, ...` (skipping names used in the equation), fixed by the conditions through `solve_for` (derivatives substituted at the point; implicit solutions only take `y(a) = b`), solutions without one being dropped. Results are tidied (`mod.rs::tidy`: smallest of the result, its expansion, `simplify` for terms with `sin` / `cos` and `Term::simplify` for rational functions). Printed `y(x) = f`, one solution per line (` \ ` in Typst).

**Other modules.** `polynom/`: `MultivariatePolynomial` (gcd, division, square-free factorization; full factorization over ℚ in `polynom/factor/`: Zassenhaus univariate, Wang/EEZ multivariate, modular and Gaussian variants), converted with `Term::to_polynomial` / `ToTerm`; `Term::factor` first replaces powers with symbolic exponents by new variables and writes rational non-integer exponents as powers of `b^(1/L)` (`factor_non_integer_powers`, since the polynomial algorithms don't terminate on them: `x + sqrt(x) = sqrt(x) (sqrt(x) + 1)`), and factors in `Z` through ℚ (`FactorThroughRationals`, Gauss's lemma), since the polynomial algorithms over `TermSet<Z>` carry non-invertible `2^-1`; dense univariate `Poly<F: Coefficient>` in `polynom/dense.rs`. Real expression shorthands shared by limits, series and integrals (`value`, `fun`, `depends`, `constant_sign`, `try_map_operands`, ...) are in `field/commons/real/expr.rs`. `matrix/`: generic `Matrix<T>` (det, inverse, row reduction; `linalg.rs`: transpose, trace, rank, kernel, characteristic polynomial; `normal_form.rs`, `eigen.rs`). `printer/`: `Print` (one line), `PrettyPrint` (2D layout: Greek letters for symbols and functions named `alpha`... (`pretty_name`), `Γ`, `ψ`, `ζ`, `W`, `⌊x⌋`, `⌈x⌉`, binomials as columns, `lim` and `∑` with their parts below (`PrettyPrinter::big_operator`), `d/dx` fractions for `diff`), and Typst output via `PrintOptions::typst()`.

**Sessions, REPL and web.** `src/dynamic.rs` (core) evaluates in a set chosen at runtime: `SetChoice` (parsed from names like `Z/7`, `M(Z)`, `R[x]`), `SetChoice::evaluate` giving an `Evaluated` (a `StatementKind` plus a type-erased printer taking any `PrintOptions`; `Display` is the default rendering, `SetChoice::eval` a string), `sets_help`, `definitions`, `clear_definitions`. `formalith-session` holds a `Session` (set, `Environment`, Typst flag) whose `run(line)` handles the commands (`:set`, `:typst`, `:defs`, `:clear`, `help`), catches panics, and returns a `Response`: an `Output` (`None`, `Result`, `Message`, `Error`) and `replay`, set for lines changing the state (definitions, assumptions, commands), which restore it when run again. `formalith-cli` is an argument parser and a `rustyline` loop over a `Session`. `formalith-web` (`wasm-bindgen` cdylib exporting `run`, returning an `Answer` with `kind`, `text`, `replay`, `set`, plus `set_typst` and `help`) runs the session in a module Web Worker (`www/worker.js`); `www/main.js` is a static terminal-like page rendering Typst results to SVG with typst.ts from jsdelivr. Panics abort the wasm instance, so the page replaces the worker after one (also how Ctrl+C works) and runs the `replay` lines again.

**Graphs and GUI.** `field/commons/real/numeric.rs`: `Numeric::compile(term, vars)` turns a `Term<R>` into a plain f64 tree (`Var(i)` for `vars[i]`, `RationalPow` giving real odd roots, `NumFn` for builtins with f64 forms, `libm` for `erf` / `gamma`, own `erfi`, `polygamma`, `zeta`, `lambertw`; anything else is `Unsupported(name)`, evaluating to NaN), serializable with feature `serde`. `formalith-session/src/graph.rs`: `Session::graph(line)` runs a line like `run` and, in `R`, gives a `Graph` (`Function` with its derivative for `y = f(x)`, expressions in `x` and one-parameter definitions; `InverseFunction` for `x = g(y)`; `Implicit` with `ImplicitRelation`s (an expression and a `Comparison`) for other relations in `x`, `y`, several for comma-separated relations with an inequality (`split_relations`), drawn as their intersection (`!=` left out) and solved by `Environment::eval` when possible, else printed as they are (`Evaluated::relations`); systems of equations are only solved; `Point` for `point(a, b)` / `(a, b)`; `Surface` for `z = f(x, y)`, expressions in `y` (with or without `x`) and definitions of two parameters; `Integral` for a whole line `integrate(f, t, a, b)` (`integral_graph`, `split_call`) with `f` in `t` and parameters and bounds free of `t`, `x`, `y`: the curve of `f` over the area between it and the axis from `a` to `b`, the line being evaluated as usual), compiled with variables `[x, y, params...]`, `params` being the other free symbols by name. In `C`, the line is evaluated in `C` (`graph::evaluate_complex`): a function of `z` (or a definition `f(z) := ...`) gives a `Surface` of its real part when its imaginary part is zero, else a `ComplexMap`, `Re f` and `Im f` of `x + i y` (`complex::parts`, `parts::split_with` mapping the variable to `x + i y`, other symbols real; for graphs only, `parts::Split::numeric` also gives parts with only a numerical form: `zeta`, `gamma` and `factorial` of non-real arguments as the internal `@zetare(a, b)`, `@zetaim`, `@gammare`, `@gammaim` (`Context::complex_part`, `NumFn::ZetaRe`..., complex Lanczos and Euler-Maclaurin with the reflection formulas in `numeric.rs` and `prelude.wgsl`), and the principal argument `2 atan(v / (|z| + u))` when `expr::arg` needs unknown signs, so `ln(z)`, `sqrt(z)` and `z^w` are drawn too), drawn as the images of the lines `Im z = k` and `Re z = k` (dimmer), integers `|k| <= 10`, `z` moving over `[-10, 10]`; a function of `x` (or a definition of another single parameter) is split with every symbol real (`complex::real_parts`), giving a `Function` when its imaginary part is zero, else a `ComplexCurve` (both parts with their derivatives), drawn per line (`plot::ComplexView`, saved in the line) as the curves of `Re f` and `Im f` (dimmer) or as the path `(Re f(t), Im f(t))`, `t` over `[-10, 10]`; a constant (no `x`, `y`, `z`, parameters allowed) gives a `Point` `(Re, Im)`; other statements have no graph there. Single relations and points are split textually (`split_relation`, `split_point`) and kept unsolved when they contain `y` (printed by `Evaluated::relation` / `Evaluated::point`); others go through `Environment::eval`. `formalith-gui`: `protocol.rs` (`Request` with every line, `Reply::Line` per line then `Done`, JSON; `Worker` reuses the result of a line whose text and preceding state-changing lines are unchanged (keyed by a hash of those), replaying state-changing lines), `evaluator.rs` (`Evaluator` over a `Backend`: a thread natively, a module Web Worker `www/worker.js` calling `worker_evaluate` in the browser, from the separate wasm module `formalith-gui-worker` (`formalith-gui` without its default feature `ui`, which gates every module but `protocol` and the recording part of `profiler`), so the interface's module has no CAS and the worker's no egui / wgpu; after a crash the first unanswered line is skipped and the backend replaced, an outdated request running over 1.5 s is dropped for the newest), Curves are sampled on the CPU in f64 (`geometry.rs`): `sample_function` takes one sample per pixel over a window around the view (the view grown by its size on each side), bisects intervals where the curve bends (down to 1/16 pixel), follows borders of the domain by bisection and cuts at jumps that don't shrink under bisection (poles and steps, drawn up to the edges or both levels), clamping values to the window grown by its height; `sample_path` (the path of a `ComplexCurve`, `t` over `[-10, 10]`) and `sample_grid` (a `ComplexMap`: the images of the lines `Im z = k` and, dimmer, `Re z = k`, integers `|k| <= 10`, `z` over `[-10, 10]`) refine by the distance of the midpoint to the chord in pixels inside the window, cut at poles by the same jump test, and clip to the window (interpolating from the closest end, which may be huge). `plot.rs` caches the polylines per line and slot (`Sampled`, keyed by revision and parameters) and samples again only when the view leaves the window or is zoomed by 1.5×; polylines are simplified in pixels (`simplify`, Douglas-Peucker to 1/8 pixel) and drawn as egui_plot `Line`s without bands (which would draw the points of a pixel column as a vertical bar, thinning steep segments), the area of an `Integral` as `FilledArea`s (`geometry::area`, between the curve and the axis from `a` to `b`). Remarkable points of the selected curve (roots, extrema, intersections with the other curves) are searched in f64 on the CPU when it or the view changes (`analysis.rs`: sign changes refined by bisection, touching zeros by golden section, extrema as zeros of `f'` or of a finite difference). The 3D view (`space.rs`, a global 2D / 3D toggle in `app.rs`, switching to 3D when a line first gives a `Surface` and no visible graph is 2D-only) draws `Surface`s (line color, shaded, grid lines) and `ComplexMap`s (height `|f|`, hue `arg f`) over the domain `center ± radius` in a box normalized to `[-1, 1]^3`, seen by an orbiting camera (drag rotates, right-drag pans, scroll zooms the domain towards the point of a surface under the pointer (`Space::hit`: the ray marched through the box with the CPU heights, refined by bisection), else its center, double-click resets; matrices by hand, wgpu depth convention); the height range is the 2nd to 98th percentile of a 33×33 CPU sample, padded; surfaces are evaluated in the vertex shader `shader/surface.wgsl` (`shader::surface`, a `RESOLUTION²` grid without vertex buffer, heights clamped and fragments outside the box or touching undefined points discarded, normals from `dpdx` / `dpdy`), drawn by `gpu/scene.rs` in `prepare` into textures of their own (4× MSAA color and depth, since egui's pass has none, resolved) then copied into the view by `paint`; the axes inside the box (where 0 is in the two other ranges) are drawn in the same pass as lines, hidden behind surfaces; the box and its ticks are painted by egui on top. Implicit relations and regions are drawn per pixel on the GPU in f32: `shader.rs` compiles a `Numeric` to a WGSL function (flattened into `let`s since WGSL has no recursion; parameters are uniforms `param(i)`, so sliders don't recompile; the sums of whole series are loops) appended to `shader/prelude.wgsl` (every `NumFn` ported to f32, NaN tested on its bits, domains checked explicitly) and the template `shader/render.wgsl`, which evaluates the relations `F_at(i, x, y) op 0` with their comparison `relation_of(i)` (emitted by `shader::render`) in each fragment: curves from a sign change on a box around the pixel, rejected when the center value is larger than the corners, with `|F| / |grad F|` coverage; with equations only their common points where the inequalities hold, else regions filled where every relation holds, each boundary drawn where the others hold, strict boundaries dashed. `gpu.rs` draws them as an egui_wgpu paint callback (a triangle covering the plot; pipelines by shader hash and uniform buffers by line in the renderer's `CallbackResources`; its tests check the prelude against `Numeric::eval` in a compute shader). `plot.rs`: egui_plot items (`GpuGraph`), hover labels from one CPU evaluation at the pointer, offscreen render tests. GPU tests skip without an adapter. The worker sends `Result` lines printed as Typst (`LineResult::typst`); `typeset.rs` (`Typesetter`, cached by source) typesets them in the interface to an SVG (white glyphs on a transparent page), natively with the `typst` crates (native-only dependencies, `typeset/native.rs`) and the vendored font `fonts/NewCMMath-Regular.otf`, in the browser asynchronously through `formalithTypeset`, defined by `www/index.html` with typst.ts from jsdelivr (the crates would add about 20 MB to the wasm; its `<script>` and `foreignObject` are stripped for resvg, its font size scaled by 4/3 since it writes points as pixels; without it, text); egui_extras' SVG loader (resvg) rasterizes it, tinted with the text color. `app.rs` (lines, sliders, the Typst toggle in Options, eframe persistence under the key `formalith`).

**Profiling.** Feature `profile` of `formalith-gui` (enabling `formalith-session/profile` and `formalith/profile`): coarse scopes with the internal macro `profile_scope!(name, data?)` (a no-op without the feature; one per crate) in the CAS (`parse_statement`, `solve`, `dsolve`, `integrate`, `risch`, `limit`, `series`, `sum`, `factor`, `simplify`, `approx`; never `normalize`), sessions and the GUI, recorded with puffin through the `profiling` crate, which also records egui, eframe and wgpu. `profiler/`: `start` / `stop` turn puffin scopes on and collect frames from a sink, converted to `Lane`s of `Frame` trees (one per thread), shown by `ProfilerWindow` (F12 or Options; `flamegraph.rs`, a table by scope). "Profile the evaluation" evaluates every line again (`Request::profile` bypasses the worker's cache) and keeps only the worker's lane, from the request sent (`request_sent`) to its `Done` (`request_done`, a newer request replacing it is profiled instead); "Record" records everything until stopped. "Only Formalith" hides scopes whose file (`Frame::file`, puffin's short path starting with the crate directory) isn't from a `formalith*` crate, their children moving up. Natively the worker thread is recorded with the interface; a Web Worker records itself when `Request::profile` is set and sends `Reply::Profile` before `Done` (puffin's clock counts from the Unix epoch in both). GPU time (`gpu/timer.rs`, timestamp features requested by `profiler::request_timestamps`): per graph inside egui's render pass (`TIMESTAMP_QUERY_INSIDE_PASSES`, native only; resolved the next frame, read back the one after), placed at the CPU time of their submission.
