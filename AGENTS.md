# AGENTS.md

Formalith is a computer algebra system library in Rust, generic over the algebraic structure (set/group/ring/field) expressions live in.

## Commands

Nightly Rust is required (`#![feature(specialization)]`); `rust-toolchain.toml` pins it, so plain `cargo` works.

- `cargo build`, `cargo test` (unit, `tests/`, doctests), e.g. `cargo test --test parser test_try_parse`
- `cargo run [expr...]` (the `cli` binary): REPL (`--set <name>` / `:set <name>`, `--typst` / `:typst`). Needs the default `cli` feature (pulls `rustyline`).
- Do not run `cargo clippy`: it hangs on this crate's recursive types. Verify with `cargo build` / `cargo test`. The crate still warns on `clippy::pedantic`, `nursery`, `cargo`, `missing_docs` and `rustdoc::all`, so every public item needs a doc comment.
- `make web` builds the wasm package into `web/www/pkg/` (needs `wasm-pack` and the `wasm32-unknown-unknown` target), `make web-serve` serves it on port 8000. `wasm-bindgen` is pinned in `web/Cargo.toml` to the installed CLI version.
- `cargo doc`: doc comments can contain Typst math as `{$ ... $}`, rendered by `docs/typstts.html` (injected by `.cargo/config.toml`).

## Architecture

**Sets** (`src/field/`). Expressions are `Term<T>` with `T: Set` a small `Copy` value describing the structure, used as a constant: `parse!("x^2", R)`. Hierarchy: `Set` → `PartiallyOrderedSet` → `Group` → `Ring` → `EuclideanRing` / `Field` / `Derivable`. Each set declares its `Element`, an `ExponantSet` (where powers live) and a `ProductCoefficientSet` (coefficient of `Mul`). Concrete sets in `src/field/commons/`:
- `N` (ordering only, no arithmetic), `Z` (`gcd`, `lcm`, `factorial` of values), `R` (rationals via `malachite`)
- `C`: Gaussian rationals over `CartesianPower<R, 2>`; the identifier `i` parses as the imaginary unit (`exp(q i pi)` is evaluated for half-integers `q`). `CartesianPower<T, K>` is only a componentwise group.
- `M`: matrices, with symbolic entries (`M<TermSet<R>>`), whose fractions are simplified by normalization (`A A^-1 = I`). `A^0` is the identity of the size of `A` (`Ring::one_like`). Also `M(Z)` / `M(Z/n)` in the REPL (`M<TermSet<Z>>`, `M<TermSet<Zn>>`). Builtins `transpose`, `kernel` (columns of a basis, a zero column for `{0}`), `eigenvalues` (column, repeated by algebraic multiplicity), `eigenvectors` (eigenspace bases as columns, same order), `hermite`, `smith` return matrices, so they are functions of `M` (`M::parse_literal` declines them, other calls parse as scalars) evaluated in `M::eval_builtin`; `det`, `trace`, `rank`, `charpoly(A, x)` (`x` by default; Berkowitz, division-free) return scalars and are also evaluated in scalar sets (`fun::eval_matrix_builtin`, in R, C, Z, Zn). Entry-specific parts go through the specialized trait `MatrixEntries`: `M(Z)` uses `matrix/normal_form.rs` (row-style Hermite `U A = H`, Smith `U A V = D` over any `EuclideanRing`, pivots normalized by `EuclideanRing::normal_unit`; rank from the Hermite form, kernel as a lattice basis), `M(Z/n)` lifts to `Z` (Hermite of `[A; n I]` reduced mod n, Smith diagonal `gcd(d_i, n)`; rank / kernel only with invertible pivots), `M` over `R` has eigenvalues (`matrix/eigen.rs`: roots of the characteristic polynomial by `solve_for`, multiplicities by derivatives, eigenspaces by an elimination testing zero on expanded numerators; unevaluated unless every root is found in `R`).
- `Zn`: `Z/nZ` with a runtime modulus and `u64` representatives; `factor` works on univariate polynomials when `n` is prime.
- `Poly<K>`: `K[x]` (`K.get_polynomial_ring(symbol!("x"))`). Values are whole expanded `MultivariatePolynomial`s, the variable parses as a value, other identifiers stay symbols. `gcd`/`lcm`/`quo`/`rem` are evaluated, `factor` is not (products of values fold back).

**Terms** (`src/term/`). `Term<T>` is an enum `Value | Symbol | Add | Mul | Pow | Fun`. `Fun` holds `Box<dyn Function<T>>`, so a function's arguments may live in another set than its result (`det` takes matrices, returns scalars). `TermSet<T>` (`term_ring.rs`) is the set whose elements are `Term<T>`s; it makes coefficients symbolic, hence types like `Term<M<TermSet<R>>>`.

**Normalize / Expand / Simplify.** Traits on `Term<T>` using specialization: a `default fn` for plain `Set` (often `todo!()`, so missing structure panics at runtime, not compile time) and real impls for `Ring`. Set-specific rules hook in through `Ring::normalize` / `expand` / `simplify` (e.g. `real.rs`, `matrix.rs`). Terms carry a `NORMALIZED` flag (`term/flags.rs`) to skip re-normalization.

**Parser** (`src/parser/`). Pratt parser, entry points `parse!` / `try_parse!`. Dispatched per set via `SetParseExpression` (`parse_literal`, optional `parse_expression` for e.g. matrix literals `[[a, b], [c, d]]`). Its `MatrixArgumentSet` is the set `det(...)` arguments parse in (`M<TermSet<Self>>` for scalar sets, `Self` for matrix sets); it must never build a bigger set from a matrix set, or the parser is monomorphized over infinitely many types. Sets without `SetParseExpression` fail at runtime. A number literal directly followed by an identifier or `(`, or a `)` directly followed by `(`, is an implicit product (`2x`, `3(x + 1)`, `(x + 1)(x - 1)`), not with a space (`5 x`) or an exponent-like identifier (`1e3`).

**Definitions** (`src/parser/environment.rs`). `a := ...` / `f(x, y) := ...` (`Parser::parse_statement`, `Environment::eval`). An `Environment` stores definitions as source text plus a snapshot of the definitions existing when they were made (so no recursion, redefinitions don't affect earlier definitions), and the parser expands them in the outermost set (`Parser::with_environment`, `parse!(input, set, &env)`), so they work in any set. Arguments are passed by name (re-parsed at each use). Names a set reserves (`i`, a polynomial variable) are declared by `SetParseExpression::is_constant`.

**Solving** (`src/solve/`). A statement of comma-separated equations, like `x + y = 3, x - y = 1`, is solved for all its symbols; `solve(a*x + y = 1, x - y = b, x, y)` solves for the listed symbols, the others being parameters (`Statement::System`, parsed by `Parser::parse_statement`; `solve` is a builtin only allowed as a whole statement). Entry point is the `Solve` trait: `solve` (every symbol, sorted by name) calls `solve_for`, specialized (unsupported by default and for `M`, real impl for rings). It writes `lhs - rhs` as a fraction (`as_fraction`), expands its numerator and tries `linear::solve` first (solutions where a denominator vanishes are dropped at the end): coefficients are extracted as terms (`Term::symbols` tells which parts contain unknowns), then Gaussian elimination with `Matrix::row_reduce_left` (pivots only in the coefficient columns) runs in the set itself when every coefficient is a value (when a pivot isn't invertible, `Z` and `Zn` fall back to `solve/lattice.rs`, specialized trait `IntegerSystem`: over `Z` the Hermite form keeps unknowns without pivot free when pivots divide their rows, otherwise both use the Smith form, `d_i y_i = c_i`, `y_i` being a new parameter `t_k` (skipping used names) when `d_i = 0`, and modulo `n` one branch per solution of `d_i y_i = c_i` with `gcd(d_i, n) > 1`, at most 256 branches), or in `TermSet` otherwise, assuming symbolic pivots are non-zero, with results simplified. On `SolveError::NonLinear` it falls back to `polynomial::solve`, a recursive case split (`Branch`): factor equations into one branch per factor, substitute unknowns with a coefficient free of unknowns (`Term::substitute`, `src/term/substitute.rs`, keeping numerators), solve univariate equations, substitute with symbolic coefficients (plus the zero-coefficient branch), eliminate with resultants (Sylvester determinant, division-free), and as a last resort solve for an unknown with symbolic coefficients. Set-specific parts go through the specialized `PolynomialRoots` trait: `factor_term` (`Term::factor` for sets meeting its bounds, `Zn::factor`, none for `Z` where `Term::factor` hangs) and `roots` (`R`: degree 1-2 and polynomials in `x^k` with radicals, cubics with rational coefficients by Cardano's formula or its trigonometric form (three real roots), quartics with rational coefficients by Ferrari's method (`quartic_roots`: a positive root of the resolvent cubic, rational if possible), signs of radicals by float approximation since `sqrt` of a negative value panics; `C`: same degrees with `k` a product of 2s and 3s, quartics by Ferrari with a rational resolvent root, cyclotomic polynomials `Φ_n` (`cyclotomic_order`) by `cos(2πj/n) + i sin(2πj/n)` when they are radicals (`trig_radical`: classic values or sums of two classic angles, so `Φ_15` but not `Φ_7`), square roots of non-real values with nested radicals; `Zn`: every residue for small moduli; `Z`: divisors of the constant; otherwise irreducible value polynomials have no roots). A `Solution` gives pivot unknowns in terms of free unknowns, several of them as `Solution::Alternatives` (printed one per line, ` \ ` in Typst), or `no solution`.

**Inequalities** (`src/solve/inequality.rs`). A statement whose comma-separated items include a comparison `<`, `<=`, `>`, `>=`, `!=` (`Parser::parse_items` returns relations, `term/relation.rs::Relation`), or such a `solve(..., x)`, is `Statement::Inequalities`, solved by the specialized trait `SolveInequality` (unsupported by default, real impl for `R`) for a single unknown without parameters; equations in the system restrict it to points (`x^2 = 4, x > 0`). Each relation `f = lhs - rhs = n/d` needs polynomials `n`, `d` in the unknown; their real roots come from `Solve::solve_for` (radicals, quartics), approximated (`approx::approximate`) to sort and merge them; truth is checked on each point and at a rational sample of each open interval, then pieces are merged into `Intervals` (`x ∈ (-oo, 1) ∪ [2, oo)`, `{0}` for isolated points, `x = 0`, `x ∈ ℝ`, Typst `in`, `union`, `RR`). An assumption on the unknown is one more relation (its root 0 added directly, since `solve` would drop it).

**Assumptions** (`src/context/assumptions.rs`). `assume(a > 0, b != 0, c <= 0, n integer)` is a whole statement (`Statement::Assume`, `Parser::parse_assume`; there each comparison compares a symbol with 0; `assume(a)` shows `a`'s assumptions). An `Assumption` is a `SignSet` (bitset of negative / zero / positive, with sign arithmetic for sums and products) plus an `integer` flag; contradicting ones are rejected. They are stored in the `Environment` (cleared by `clear`, listed by `repl::definitions` as an `assume(...)` line, `:clear a` removes them) and installed in a thread-local by `Parser::parse` / `parse_statement` when the parser has an environment (`Assumptions::enter`, a guard restoring the previous ones), so parallel tests don't share them and `parse!(input, R)` without environment has none. Everything queries them through `assumption(symbol)` and the sign engine `field/commons/real/sign.rs`: `sign_set(term, mode)` from the structure (values, `pi`, `e`, assumed symbols, sums, products, powers, `exp`, `abs`, odd functions...), with `SignMode::STRUCTURAL` (in normalization), `APPROXIMATE` (also approximating constants; `constant_sign` is this) and `GENERIC` (also unassumed parameters non-zero; limits' `const_sign`), and `is_integer`. In `R`: `abs(u)` drops when `u` is non-negative / non-positive (so `sqrt(x^2) = x`, `ln|x| = ln x`), `sign`, `floor` / `ceil` of integers, `(c u)^e` distributes over positive symbols, `sin` / `cos` / `tan` of `u + n pi` with an integer `n` give `(-1)^n`, whose exponent is reduced modulo 2 (`R::reduce_parity`). Integrals use it for `ln` vs `ln|u|` (`integrate::is_positive`), limits for signs of parameters (`lim(exp(a x), x, oo) = oo` with `a > 0`). `solve` drops solutions contradicting assumptions on unknowns and branches with an equation that can't vanish (specialized trait `Assumed` in `solve/polynomial.rs`, real impl for `R`), and real roots use assumed signs of discriminants.

**Symbols** (`src/context/`). `Symbol` is a `usize` id interned in a global `RwLock<Context>`; create with `symbol!("x")`. Builtins have fixed ids from `Context::BUILTIN_NAMES`: append new ones at the end, and set their arity in `Context::builtin_arity` (one argument by default; checked by the parser). Builtins are evaluated in the set's `normalize` (e.g. `R::eval_builtin`). In `R`, `cot`, `sec`, `csc` and `log(x, b)` (base 10 by default) are rewritten there with `cos`, `sin` and `ln`, so they never survive as functions; `e^u` is rewritten as `exp(u)`, `exp(u)^c` as `exp(c u)` and products of exponentials as one `exp`; roots of products of positive constants are distributed (`sqrt(2 pi) = sqrt(2) sqrt(pi)`). `asin`, `acos`, `atan`, the hyperbolic functions and their inverses, `erf`, `erfi`, `factorial` and `binomial` stay functions, with exact values at classic points (inverse trigonometric values match radicals by their square, `sqrt(1/3)` like `sqrt(3)/3`; `factorial` of half-integers, `binomial(n, k)` for rational `n`), derivatives (`term/derivative.rs`, also `b^e` with a variable exponent and `integrate(f, t, a, b)` with bounds depending on `x`; none for `binomial`) and approximations. The Gamma family (`real/special.rs`): `gamma`, `polygamma(m, x)` and `zeta` stay functions, `beta(a, b)` is rewritten with `gamma` and `digamma(x)` as `polygamma(0, x)`; exact values of `gamma` at integers and half-integers, of `polygamma` there with the constant `euler_gamma` (Euler-Mascheroni), `ln 2` and `zeta(m + 1)`, and of `zeta` at even and non-positive integers (cached exact Bernoulli numbers, `special::bernoulli`); derivatives `gamma' = gamma psi`, `factorial' = factorial psi(x + 1)`; approximations by shifting the argument up then asymptotic series (`Fixed::gamma`, `digamma`, `hurwitz_zeta` for `polygamma` and `zeta(s)`, `s > 1`). In Typst they print as `Gamma`, `psi^((m))`, `zeta`, `gamma`. `lambertw(x)` is the principal branch `W_0` (`real/special.rs::eval_lambertw`: `W(0)`, `W(e)`, `W(c e^c) = c` for rational `c >= -1`; derivative `W/(x (1 + W))`, sign of its argument, Newton's iteration in `Fixed::lambert_w`, printed `W` in Typst). `piecewise(c1, v1, c2, v2, ..., default)` (`special.rs::eval_piecewise`): the parser accepts comparisons only as its conditions (`Parser::parse_piecewise_args`), stored as internal functions `@lt(lhs, rhs)`, `@le`, `@gt`, `@ge`, `@eq`, `@ne` (`term/relation.rs::Relation`, printed `lhs < rhs`); conditions are decided by `sign_set(lhs - rhs, APPROXIMATE)`, false ones dropped, a leading true one gives its value, none left gives the default or `undefined`; derivatives are taken branch-wise, Typst prints `cases(...)`. `diff(f, x, n)` is the `n`-th derivative (`fun::eval_calculus_builtin`). `apart(f, x)` (variable optional when `f` has a single symbol) is the partial fraction decomposition over ℚ (`integrate/apart.rs`, `Term::apart`: per irreducible `q^e` of the denominator, the numerator by `inverse_mod` of the cofactor, then its `q`-adic digits), unevaluated for symbolic coefficients. Odd and even functions take the sign out of their argument (`sin(-u) = -sin(u)`, `cos(-u) = cos(u)`), `sin`, `cos`, `tan` of `u + q pi` reduce `q` (quarter turns for half-integers, else into `(-1/2, 1/2)`), and have radical values at multiples of `pi/12`, `pi/10` and `pi/8` (`eval_trig_at_pi_multiple`); `ln(q) = -ln(1/q)` for `0 < q < 1`; `exp(q ln c) = c^q` for rational `q` and a positive value `c`; `(c u)^e = c^e u^e` when `c^e` is rational (`sqrt(4 x^2) = 2|x|`), and `sqrt(a + b sqrt(c))` is denested when possible. `pi`, `e`, `euler_gamma`, `oo` (infinity) and `undefined` (a limit that doesn't exist) are builtin constants (`Context::is_builtin_constant`, arity `(0, 0)`): symbols that can't be defined and aren't unknowns of `solve`. Terms with `oo` factors are never merged by the generic normalization (`Term::is_infinity_factor`), and `0 oo` is `undefined`; `R::eval_infinite` does the rest: `oo - oo` is `undefined`, finite constants are dropped from sums with `oo` (symbols are kept, `x + oo`), products with positive constants and positive powers are `oo`, `oo^-n = 0`, and `undefined` absorbs sums and products. Functions have their limits as values at `oo` (`exp(-oo) = 0`, `atan(oo) = pi/2`). The builtins `expand` and `simplify` do more in `R` than internal expansions (`real/rewrite.rs`): addition formulas for `sin` / `cos`, and for `simplify` the smaller of the plain simplification and that of the term rewritten with `exp(c ln u) = u^c` (`expr::exp_of_ln`, not a normalization rule since limits and integrals build `exp(g ln b)`), integer quotients of logarithms, hyperbolic functions as `exp`, multiple angles and `sin^2 = 1 - cos^2`.

**Approximation** (`src/field/commons/real/approx.rs`). `approx(x, digits)` (15 significant digits by default) evaluates the numerical parts of an `R` expression with fixed-point integer arithmetic (`exp`, `ln`, `sin`, `cos`, `tan`, roots, `pi`, `e`; other builtins are normalized on approximated arguments), raising the working precision until the result has enough significant bits, then rounds to an exact `Rational`. Results carry the `APPROXIMATE` flag (`term/flags.rs`, on a `Value`, or on a `Mul` for its coefficient), printed as decimals through `Set::print_approximate`. The flag is contagious when constants are merged (`Term::try_merge_terms` / `try_merge_factors`, `Mul` normalization), and powers or builtins of approximated values are approximated in `R::normalize`; other rewrites may drop it.

**Limits** (`src/limit/`). `lim(f, x, a)`, or `lim(f, x, a, 1)` / `lim(f, x, a, -1)` for right / left limits, is evaluated in `R::normalize` through `Term::limit` (`R` only; it evaluates to `undefined` when the limit doesn't exist, and stays unevaluated when it is unsupported or unknown, see `LimitError`). `floor(g)` / `ceil(g)` are first replaced by their constant value near the point (`remove_steps`, from `lim g`, and at an integer from the sign of `g - n` on each side). Powers with an exponent depending on `x` are then rewritten as `exp(g ln b)`, `tan` as `sin / cos`, `sign(u)` as `u / |u|`, `min` / `max` with `abs`, hyperbolic functions and their inverses with `exp` / `ln`, `asin` / `acos` with `atan`, and `factorial` / `binomial` with `gamma` (`exp_log_form`), so `atan` is the only inverse function the series engine handles (`atan a = ±pi/2 - atan(1/a)` at infinity). `erf` has a Taylor series at finite points (Hermite polynomials, also `erfi`); `erf g` with `g -> ±oo` is rewritten as `±(1 - exp(-g^2) erfcx(±g))` before `mrv` (`erf_at_infinity`), and `erfi g` as `±exp(g^2) erfix(±g)`, the internal `@erfcx` and `@erfix` having asymptotic series in `1/g`. Likewise `gamma g` with `g -> oo` is rewritten by Stirling's formula `exp((g - 1/2) ln g - g + ln(2 pi)/2 + @lgammastar(g))` (`special_at_infinity`), `-oo` being unsupported. The series engine expands `gamma` and `polygamma` at finite points (`gamma(a0 + u) = gamma(a0) exp(sum psi^(j-1)(a0) u^j / j!)`, Laurent series at poles through the recurrence) and `polygamma(m, g)` at `+oo` by its asymptotic series. At a finite point, `f` is evaluated directly when no singularity is met (`eval_at`), otherwise every limit is reduced to `x -> +oo` (`x -> a + 1/x`, `a - 1/x`, `-x`; two-sided limits compute both sides). There, the Gruntz algorithm (`gruntz.rs`) takes the most rapidly varying subexpressions (`mrv`, `x` or exponentials, moved up with `x -> exp(x)` when `x` is one of them), rewrites them as `A w^c` with `w -> 0^+` (`rewrite`, `ln w` becoming an expression in `x`), and takes the leading term `c0 w^e0` of a truncated series in `w` (`series.rs`: exponents are constant terms, possibly irrational like `ln 2 / ln 3`, compared numerically; coefficients may contain `x`; absolute orders are raised until a non-zero leading coefficient is found). The limit is 0, `±oo` by the sign of `c0`, or the limit of `c0`. Zero tests simplify, then approximate (constants) or evaluate at a few rational points (coefficients in `x` and angles); other parameters are assumed non-zero unless assumed otherwise (signs of constants go through the sign engine, see Assumptions). The entry point `Gruntz::limit` adds, around the internal `limit_infinity`: `sin g` / `cos g` with `g -> ±oo` get an angle `@t<n>` in place of `g` (a constant for the algorithm, linked as `k t + d` to an earlier angle when `g ~ k g_t + d`, `remove_oscillations`); `check_bounded` requires every division, `ln` or root of a term with angles to stay away from 0 (interval arithmetic in `bounds.rs`), else `Unknown`; a result depending on a single angle is `Undefined`, a constant one (checked at sample angles with `approximate_fixed`) is kept; an infinite limit whose sign depends on parameters is `sign(a)*oo` (only at the top level, internal limits only use exact `±oo`). Two-sided limits are `Undefined` only when both sides surely differ. Recursion is bounded (`MAX_DEPTH`).

**Series** (`src/limit/expansion.rs`). `series(f, x, a, n)` (default `n = 6`, optional side `1` / `-1` like `lim`) gives the terms of `f` below `(x - a)^n` (below `x^-n` at `±oo`), without the remainder, evaluated in `R::normalize` through `Term::series`. It substitutes `x -> a ± w` (`±1/w` at `±oo`), runs the Gruntz series engine (`series::expand`, `w -> 0^+`, `ln w` as a placeholder replaced by `ln(x - a)`), and substitutes back (`ln w` as `-ln(s x)` at `s oo`). Exponents may be negative or fractional. Two-sided series compute both sides and must agree (`abs(x)`, `sqrt(x)` at 0 stay unevaluated); non power series (`exp(x)` at `oo`, `exp(1/x)` at 0) stay unevaluated.

**Integration** (`src/integrate/`). `integrate(f, x)` and `integrate(f, x, a, b)` are evaluated in `R::normalize` through `Term::integrate` / `Term::integrate_definite` (`R` only; unevaluated when no antiderivative is found, `oo` / `-oo` / `undefined` for divergent definite integrals, see `IntegrateError`). `Integrator` (`mod.rs`) is a recursive search bounded by `MAX_DEPTH`, caching results by `(variable, integrand)`, substitution variables being `@i<depth>`: rational functions of `x` with rational coefficients go to `rational.rs` (always, dense `Poly` over ℚ (`polynom/dense.rs`, shared with the univariate factorization; `poly.rs` converts terms): polynomial part, Hermite reduction, then per irreducible factor `q` of the square-free denominator the residue polynomial `p = A D'^-1 mod q`, a constant giving `c ln|q|`, otherwise roots of `q` in `C` by radicals (`PolynomialRoots`, `split_complex` in `solve/polynomial.rs`) giving `ln|x - r|` for real roots and `ln` + `atan` for conjugate pairs; `None` when the roots can't be computed). Other integrands: sums term by term, constant factors out, then the first strategy that succeeds among `table.rs` (functions of linear arguments including `erf` / `erfi`, `1/(A x^2 + B)` with symbolic `A`, `B` as `atan`, square roots of quadratics, `e^u sin v`, `p e^q` for polynomials `p` and quadratic `q` with `erf` / `erfi`, products of exponentials merged), `trig.rs` powers (`sin^m cos^n` with `t = cos`, `sin` or `tan`, or power reduction), `substitution.rs` (derivative-divides on subexpressions, `replace` also maps `b^q` to `t^(q/p)` and `exp(c)` to `t^(c/a)`; `b = exp(t)` for `u = ln b`, results go through `exp_of_ln`; linear `u` also substitutes `x`), `trig::substitute` (rational functions of `x` and `sqrt(q)`, `q = a u^2 + k` quadratic with rational coefficients: `u = r sin t`, `r / cos t` (for `u > r`) or `r tan t`, the result in `t` written back with `sqrt(q)` after mapping `sin(n t)`, `cos(n t)`, `tan(t/2)`; rejected when it grows too much), `parts.rs` (logarithms and inverse functions, then polynomial factors), `trig.rs` rewrites (hyperbolic functions as `exp`, product-to-sum, also merging factors of the same argument and reducing powers when the product has a non-trigonometric factor, so `e^x sin x cos x` becomes terms of `table.rs`'s `e^u sin v`, Weierstrass `t = tan(u/2)`), then the Risch algorithm (`risch/`), and finally the expanded integrand. The Risch algorithm (transcendental case, Bronstein) writes the integrand in a tower `QQ(x, t_2, ..., t_n)` of `exp` / `ln` monomials (`tower.rs`: `b^g` as `exp(g ln b)`, hyperbolic functions as `exp`; a new monomial is checked against the Risch structure theorems by evaluating at sample points and solving over ℚ, dependent ones are written with existing monomials, rebuilding with `exp(b/q)` first when `exp(a)` is a non-integer power of `exp(b)`; other functions, roots and symbols are unsupported). Elements (`polynom/fraction.rs`) are canonical nested fractions of dense `Poly<Elem>` (`polynom/dense.rs` is generic over `Coefficient`). Integration in `K(t)` (`mod.rs`): Hermite reduction with the derivation, Rothstein-Trager residues (resultant interpolated in `z`; non-constant residues prove non-elementarity, irrational ones above `QQ(x)` are unsupported), then the polynomial part: limited integration of coefficients for `ln`, Risch differential equations (`rde.rs`: weak normalization, normal / special denominators, degree bounds, SPDE, non-cancellation and recursive cancellation cases) for `exp`. Undecided steps are `RischError::Unsupported`, so `IntegrateError::NonElementary` (returned by `Term::integrate`, the integral stays unevaluated) is a proof. Substitutions `b = t^(1/p)` for `u = b^p` are only done for integer ratios or positive `b`. Logarithms are `ln|u|` unless `u` is provably positive (`is_positive`). Definite integrals (`definite.rs`) on `[0, oo)` first try Mellin-type integrals (`mellin`: `x^(s-1)` times `e^(-c x)` gives `gamma(s)/c^s`, times `1/(e^(c x) - 1)` gives `gamma(s) zeta(s)/c^s`, times `1/(e^(c x) + 1)` with the factor `1 - 2^(1-s)`). Then they replace sums and functions of inverse trigonometric functions that are constant on the open interval by their value (`constant_parts`: no singular point inside, and the derivative is exactly zero once square roots of squares of rational functions are written with their sign on the interval; evaluated at a point with exact values when possible), and on finite symmetric intervals `[-b, b]` integrate `f(x) + f(-x)` on `[0, b]` when it is a rational function in the Risch tower and `f` is not (`1/(e^x + 1) + 1/(e^-x + 1) = 1`, odd functions give 0; `f` must be continuous). They then split `[a, b]` at the singular points of `f` and `F` (real roots of polynomial denominators, zeros of `sin` / `cos` in denominators, poles of `tan`; other denominators are sampled for a sign change, else `Unsupported`) and sum one-sided `Term::limit`s of `F`; at regular bounds the substituted value is preferred when it agrees numerically (limits rewrite `tan`). Symbolic bounds are only allowed when `f` and `F` are regular. `approx(integrate(f, x, a, b))` uses double exponential quadrature in `Fixed::integrate` (`approx.rs`: tanh-sinh, exp-sinh, sinh-sinh by the bounds), halving the step until two results agree to half the precision; nodes are bound without normalization (`bind`).

**Sums and products** (`src/sum/`). `sum(f, k, a, b)` and `product(f, k, a, b)` (arity 4, bounds may be `-oo` / `oo`) are evaluated in `R::normalize` through `Term::sum` / `Term::product` (`R` only; `SumError::Divergent` gives `±oo`, `Undefined` gives `undefined`, `Unsupported` leaves them unevaluated). Integer value bounds with at most 100 terms are computed term by term (`expr::subs`, which also substitutes in exponents), so are larger ranges up to 1000 terms when no closed form is found. Otherwise an antidifference `F` (`F(k + 1) - F(k) = f(k)`, `mod.rs::antidifference`) gives `F(b + 1) - F(a)`, the first strategy that succeeds among: constant factors out, `binomial(u, m)` with a small natural `m` expanded as a polynomial, polynomials in `k` by Faulhaber's formula (`polynomial.rs`, Bernoulli numbers from `special::bernoulli`), geometric terms `r^k p(k)` (`r != 1` assumed), Gosper's algorithm (`gosper.rs`: the ratio `t(k + 1)/t(k)` built structurally from rational functions, `c^(alpha k + beta)`, `exp`, `factorial` / `gamma` / `binomial` of linear arguments with integer slopes; Gosper form with the shifts found as natural roots of a resultant computed with the parameters specialized at sample points, then checked exactly; key equation solved by undetermined coefficients with a degree bound), rational functions over ℚ whose denominator has rational roots as `polygamma` (`sum(1/k, k, 1, n) = psi(n + 1) + euler_gamma`), then sums term by term. Coefficients are in `QQ(t_1, ..., t_n)` (`field.rs::Params`), every maximal subterm free of `k` being a generator, using the nested fractions `Elem` of `polynom/fraction.rs` (shared with the Risch algorithm, with `interpolate`, `sample_points` and `solve_linear`). Values at a removable singularity of `F` and infinite bounds are limits (`mod.rs::limit`, over a fresh real variable `@k` not assumed integer, with `c^g` for a negative `c` rewritten as `|c|^g cos(pi g)`, since `lim((-1)^x, x, oo)` is wrongly 0); the computation runs with `k` assumed integer. Infinite sums without antidifference try known series (`zeta(s)` for `k^(-s)`, `exp(x)` for `x^k / k!`). Products use an antiquotient `G` (`product.rs`): `c^k`, multiplicative over factors and constant powers, `c^g` as `c^(antidifference g)`, linear factors `alpha k + beta` as `alpha^k gamma(k + beta/alpha)` (a factorial when `beta/alpha` is an integer), polynomials with rational roots; `G(b + 1)/G(a)` (unsupported at poles), then `combine_factorials` merges factorials whose arguments differ by integers (`(n + 1)!/n! = n + 1`, `u/u! = 1/(u - 1)!`). Results are tidied (`mod.rs::tidy`: smallest of the result, its expansion, and for rational functions its simplification and factorization; `simplify` may not terminate on other terms). Typst prints `sum_(k = a)^(b) f`, the pretty printer a `∑` / `∏` column (`PrettyPrinter::big_operator`).

**Differential equations** (`src/ode/`). `dsolve(y' = x*y)`, `dsolve(y'' + y = 0, y(0) = 1, y'(0) = 0)` or `dsolve(diff(y(t), t) = t, y, t)` is a whole statement (`Statement::Ode`, `Parser::parse_dsolve`; builtin `dsolve`, the lexer's `'` token `TokenKind::Prime` is only accepted there). Trailing identifier arguments name the function and the variable, otherwise the function is the first identifier followed by `'` (else called like a function) and the variable its symbol argument, or `x`. Arguments `y'(a) = b` with `a` not the variable are initial conditions (`Condition`), the single other one the equation, parsed with `Parser::with_ode`: `y`, `y(x)` and `y''` become `y(x)` and unevaluated nested `diff(y(x), x)`. The `Dsolve` trait is specialized (unsupported by default, real impl for `R`); it replaces `y(x)` and its derivatives by placeholders `@y0, @y1, ...` (`y` elsewhere is unsupported). First order (`first_order.rs`): `e = 0` is solved for `@y1` with `Solve::solve_for`, each slope `F(x, y)` is linear (`dF/dy` free of `y`, integrating factor `exp(-integrate(a))`, `ln|u|` written `ln u` there since only a constant factor matters) or separable (factors free of `y` / of `x`, `exp` of sums split, `Term::factor` for rational functions), `G(y) = H(x) + c` being inverted for sums of rational multiples of logarithms (`p(y) = c exp(d H)`, the constant absorbing the sign), `alpha exp(u(y))`, or by `solve_for`, and kept implicit (`OdeBranch::Implicit`) otherwise. Higher orders (`linear.rs`) need constant rational coefficients: characteristic polynomial as a dense `Poly`, square-free parts for multiplicities, `rational::factor` then `PolynomialRoots` in `C` split with `rational::split` (`x^j exp(u x)`, with `cos(v x)` / `sin(v x)` for `u ± i v`), and a particular solution by variation of parameters (Wronskian system solved with `solve_for`, `u_i'` simplified then integrated, terms proportional to the basis dropped). Constants are `c_1, c_2, ...` (skipping names used in the equation), fixed by the conditions through `solve_for` (derivatives substituted at the point; implicit solutions only take `y(a) = b`), solutions without one being dropped. Results are tidied (`mod.rs::tidy`: smallest of the result, its expansion, `simplify` for terms with `sin` / `cos` and `Term::simplify` for rational functions). Printed `y(x) = f`, one solution per line (` \ ` in Typst). Constant solutions of separable equations (`g(y) = 0`) aren't listed.

**Other modules.** `polynom/`: `MultivariatePolynomial` (gcd, division, square-free factorization; full factorization over ℚ in `polynom/factor/`: Zassenhaus univariate, Wang/EEZ multivariate, modular and Gaussian variants), converted with `Term::to_polynomial` / `ToTerm`; dense univariate `Poly<F: Coefficient>` in `polynom/dense.rs`. Real expression shorthands shared by limits, series and integrals (`value`, `fun`, `depends`, `constant_sign`, `try_map_operands`, ...) are in `field/commons/real/expr.rs`. `matrix/`: generic `Matrix<T>` (det, inverse, row reduction; `linalg.rs`: transpose, trace, rank, kernel, characteristic polynomial; `normal_form.rs`, `eigen.rs`). `printer/`: `Print` (one line), `PrettyPrint` (2D layout), and Typst output via `PrintOptions::typst()`.

**REPL and web.** `src/repl.rs` (`SetChoice`, `sets_help`, `definitions`, `clear_definitions`) holds the evaluation logic shared by `src/bin/cli.rs` and `web/` (`formalith-web` workspace member, `wasm-bindgen` cdylib exporting `evaluate`, `is_definition`, `definitions`, `clear_definitions`, `set_name`, `sets_help`). `web/www/` is a static terminal-like page: evaluation runs in a module Web Worker, results are printed as Typst and rendered to SVG with typst.ts from jsdelivr. Panics abort the wasm instance, so the page replaces the worker after one (also how Ctrl+C works).
